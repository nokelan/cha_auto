# 코드 기능별 분리 + 지출결의서 자동 상신 구축 계획

작성: 2026-10-21

## 요청 (원문 요약)

- 수정사항
  - 문서 비교와 계약서 목록을 별도의 파일로 만들어 코드를 나눈다.
  - 계약서 목록의 각 계약서에 거래명세서 또는 지출결의서 생성 버튼을 넣는다.
- 추가 기능
  1. 지출결의서 버튼을 누르면 `https://sbgw.vercel.app/#/draft`에 접속해 기안을 작성한다.
  2. 양식은 '지출결의서'를 고른다.
  3. 나머지 칸은 계약서 내용에 맞게 입력한다.
  4. 모든 기능은 스크립트로 하고, AI 없이 동작한다.
  5. 입력을 마치면 '상신'을 누른다.
  6. 화면이 작성본으로 바뀌면 그 화면의 금액이 정확한지 검토한다.
  7. 검토가 끝나면 로컬 계약서 목록에서 그 계약서의 상태를 '품의완료'로 만든다. 다른 경우의 상태는 '없음'이다.

## 사용자 결정 (2026-10-21)

- **코드 분리**: 서버와 화면 모두 기능별로 나눈다. 동작은 바꾸지 않는다.
- **입력 방식**: 확인 창을 거쳐 자동 상신한다.
  - 확인 창에 계약서 값(제목·청구월·공급가액·세액·합계·첨부)을 미리 채워 보여 준다.
  - [상신]을 누르면 스크립트가 그룹웨어 입력 → 상신 → 작성본 검토를 자동으로 한다.

## 그룹웨어 기안 화면 조사 결과 (`app.js`)

- 입력 칸
  - 양식 `#f-form`: 지출결의서, 수입결의서, 품의서
  - 제목 `#f-title`
  - 계약 `#f-contract`: 값은 관리번호
  - 청구·사용 월 `#f-month`: YYYY-MM
  - 공급가액 `#f-supply`, 부가세 `#f-vat`, 합계 `#f-total`: 합계는 자동 계산하지 않는다.
  - 첨부: `name="attachments"` 체크박스. 값은 사이트의 파일 이름이다.
  - 특이사항 `#f-note`: 비우면 "없음"
  - 상신 `[data-testid=submit]`, 오류 표시 `[data-testid=form-error]`
- 상신하면 `#/doc/U-n`으로 이동한다. 작성본에서 읽을 수 있는 값은 다음과 같다.
  - 문서번호
  - `[data-testid=doc-title]`
  - `[data-testid=doc-amount]`: `KRW 2,310,000`
  - `[data-testid=doc-content]`: "2. 업 체 명 : …", "4. 사용기간 : 26.09", "5. 금 액 : 2,310,000원 (공급가액 2,100,000원 / 세액 210,000원)"
  - 상태 배지
- 기안은 사이트 서버가 아니라 그 브라우저의 저장소(localStorage)에 저장된다. 그래서 앱의 그룹웨어 전용 브라우저 프로필에 남는다.
- 사이트 기존 지출결의서의 관례
  - 제목: `[IT기획팀] {거래처} {서비스} 지출의 건 (YY.MM월)`
  - 첨부: `세금계산서_{상호}_{YYYY-MM}.pdf`와 계약서 PDF

## 설계

### 1. 코드 분리 (동작 불변)

**서버**: `saebom.service.Service`와 `saebom.api.create_app`의 import 경로와 동작은 그대로 둔다.

- `saebom/services/`: 기능별 믹스인
  - `core.py`: 초기화, 작업 제출·갱신, 브라우저, `download_one`, 설정·저장 위치
  - `compare_service.py`: 문서비교. 목록 동기화, 추천, 다운로드, 비교, 보정
  - `contracts_service.py`: 계약서 목록. 가져오기, 목록, 거래명세서, 지출결의서, 상태
  - `local_audit_service.py`: 로컬 세금계산서 대조
  - `service.py`는 `class Service(Core, CompareMixin, ContractsMixin, LocalAuditMixin)` 조합과 공용 도우미 재수출만 맡는다.
- `saebom/routes/`: 기능별 `register(app, service, store)` 함수
  - `compare.py`, `contracts.py`, `local_audit.py`, `system.py`(상태·설정·종료·인증 외)
  - `api.py`에는 앱 생성, 미들웨어, 인증, 공용 모델만 남긴다.
- 기존 테스트는 고치지 않고 통과해야 한다. 고쳐야 하면 import 경로만 고친다.

**화면**
- `screens/compare/`: MailsScreen, ResultView, HistoryScreen 이동
- `screens/contracts/`: ContractsScreen(컨테이너), ContractList, ContractDetail, ContractActions(거래명세서/지출결의서 버튼과 꺼진 이유)
- `components/`: StatementModal, ExpenseModal

### 2. 계약서 행 버튼

- 목록의 각 행과 상세 제목줄에 버튼을 하나 둔다. 구분에 따라 버튼이 다르다.
  - 수입 계약: **거래명세서 생성**(기존 확인 창)
  - 지출 계약: **지출결의서 상신**(새 확인 창)
- 원문 PDF가 없거나 다른 작업이 진행 중이면 버튼을 끄고 이유를 보여 준다.
- 목록과 상세에 상태 배지 **품의완료/없음**을 보인다.

### 3. 지출결의서 (서버 `saebom/expense.py` + `SiteClient.submit_expense`)

1. **초안** `GET /api/contracts/{id}/expense`: 지출 계약만 대상이다.
   - 양식: 지출결의서
   - 제목: `[IT기획팀] {거래처} {계약명에서 '계약서' 뺀 서비스명} 지출의 건 (YY.MM월)`
   - 청구월: 기본값은 오늘 기준 직전 달이다. 계약기간 밖이면 가장 가까운 기간 안의 달로 맞춘다.
   - 금액: 계약서 판독값에 판정 규칙(`compare` 기대값)을 적용해 공급가액·세액·합계를 낸다. 부가세 포함 계약이면 ÷1.1이다. 총액 계약은 경고하고 사람이 고친다.
   - 첨부 후보: 계약서 PDF 이름, `세금계산서_{상호}_{YYYY-MM}.pdf`
   - 특이사항: 비움
   - 마지막 상신 정보와 중복 경고(같은 달 품의완료가 이미 있음)를 함께 준다.
2. **상신** `POST /api/contracts/{id}/expense`: 확인 창에서 고친 값을 받아 "지출결의서 상신" 작업을 접수한다.
3. **작업**(작업 스레드에서 Playwright로 실행)
   1. `#/draft`로 간다.
   2. 양식을 고르고 제목을 입력한다.
   3. 계약 option을 확인하고 고른다. option이 없으면 오류로 끝낸다.
   4. 월·금액·특이사항을 입력한다.
   5. 첨부는 사이트 체크박스 중 이름이 같은 것만 체크한다. 없는 파일은 경고로 남긴다.
   6. 상신 버튼을 누르고, 폼 오류 문구가 보이면 실패로 끝낸다.
   7. `#/doc/` 이동을 기다린 뒤 작성본의 값을 읽는다.
4. **검토** `expense.review(입력값, 작성본)`: 순수 함수다. 항목은 다음과 같다.
   - 금액 칸 = 합계
   - 본문 '금 액'의 합계·공급가액·세액 = 입력값
   - 공급가액 + 세액 = 합계
   - 업체명 = 계약 거래처
   - 사용기간 = 청구월
   - 제목이 같음
5. **상태**
   - 모든 항목이 일치하면 **품의완료**다. 하나라도 다르면 상태는 **없음**으로 두고 검토 결과를 보여 준다.
   - 저장: 새 테이블 `contract_status(id PK, status, data JSON, updated)`
     - data: `{month, doc_id, doc_no, doc_url, title, supply, vat, total, review[], warnings[], submitted_at}`
   - `GET /api/contracts`의 각 계약에 `status`('없음' 기본값)와 `approval`(data)을 붙인다.
6. **확인 창**(`ExpenseModal`)
   - 값 입력, 합계 검산 표시, 경고, [상신]
   - 작업이 진행되는 동안 진행 표시를 보이고, 끝나면 결과를 보여 준다.
     - 문서번호, 작성본 금액, 검토 항목표, 상태
     - 그룹웨어 작성본 열기 링크

## 가정

- 상태는 계약 단위로 마지막 상신 1건을 기준으로 한다. 다른 달을 상신해도 마지막 결과로 바뀐다.
- 같은 달을 다시 상신할 수 있다. 확인 창에서 경고만 한다.
- 그룹웨어 기안은 앱의 전용 브라우저 프로필에 저장된다. 다른 브라우저에서는 보이지 않는다(사이트의 특성).
- 수입 계약의 수입결의서 자동 상신은 이번 범위에서 뺀다.
