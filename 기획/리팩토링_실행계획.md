# 07_auto 리팩토링 실행 계획 (2026-10-21)

## Context
`기획/리팩토링_분석_리포트.md`에서 찾은 문제를 해결한다. 사용자는 **리포트 전체 범위**를 선택했고, **서브에이전트 병렬 처리로 최대한 빠르게** 진행하기를 원한다.

리포트가 짚은 문제는 다음과 같다.
- `frontend/src/main.tsx` 한 파일이 비대하다(403줄, 67KB, 400자 넘는 줄 32개).
- 폴링할 때마다 전체 조회가 반복되는 N+1 구조다(`catalog()`, `/api/results`).
- 비밀번호·사이트 주소·자사 사업자번호가 소스에 하드코딩돼 있다.
- `Service` 클래스의 책임이 너무 많다.
- 함수가 길고 코드가 중복된다.

**목표: 동작과 판정 결과는 그대로 두고 구조와 성능만 개선한다.** 비밀번호는 설정으로 분리하되 기본값 `0000`을 유지하고, 환경변수 `SAEBOM_PASSWORD`로 바꿀 수 있게 한다. 5회 연속 실패하면 30초 동안 잠근다.

**제약**
- 07_auto 지침에 따라 모든 새 파일·함수에 한글 파일 역할 주석과 기능명세(목적·입력·출력·처리·예외·부수효과)를 붙인다. 함수를 옮기면 명세도 함께 옮기고 갱신한다.
- 프런트의 무의미한 인라인 콜백 주석은 정리하고, 주요 콜백의 명세만 남긴다.
- 07_auto는 git 저장소가 아니다. 그래서 시작 전에 백업을 만든다.

## 0단계 — 메인이 직접 수행 (병렬 시작 전, 몇 분 소요)
1. **백업:** `saebom/`, `launcher.py`, `frontend/src/`, `tests/`, `scripts/`를 `tmp/refactor-backup-2026-10-21/`로 복사한다.
2. **계획서 사본 저장:** 이 계획을 `기획/리팩토링_실행계획.md`로 저장한다(07_auto 지침).
3. **공통 모듈 생성:** 세 에이전트가 함께 쓰는 모듈을 먼저 만들어 충돌을 막는다.
   - `saebom/config.py`
     - `SITE_URL="https://sbgw.vercel.app/"`, `SITE_HOST`
     - `APP_PASSWORD = os.environ.get("SAEBOM_PASSWORD", "0000")`
     - `OWN_BIZ="000-81-00001"`
     - `MAX_PDF_BYTES=50MiB`, `MAX_PDF_PAGES=100`, `MAX_PAIRS=500`
     - `LOGIN_MAX_FAILURES=5`, `LOGIN_LOCK_SECONDS=30`
   - `saebom/files.py`
     - `safe_name(name)`: `service.py:286`과 `store.py:189`에 중복된 정규식을 하나로 합친 것
     - `KIND_FOLDERS={"invoice":"세금계산서","contract":"계약서"}`
4. **기준선 기록:** venv `pytest`(17건 통과)와 `npm run build` 결과를 기록한다.

## 1단계 — 서브에이전트 3개 병렬 (파일 소유권을 엄격히 분리)
에이전트끼리 같은 파일을 수정하지 않는다. 기존 `tests/test_app.py`는 어느 에이전트도 고치지 않는다. 필요한 테스트는 각자 새 파일로 추가한다.

### 에이전트 A — 프런트엔드 (소유: `frontend/src/**`)
- **파일 분할:** `main.tsx`를 다음과 같이 나눈다.
  - `types.ts`, `api.ts`(`api`, `stamp`, `display`)
  - `components/Badge.tsx`, `components/Pdf.tsx`, `AccessGate.tsx`, `App.tsx`
  - `screens/MailsScreen.tsx`(3단 화면), `screens/ResultView.tsx`, `screens/HistoryScreen.tsx`, `screens/SettingsScreen.tsx`
  - `components/EditModal.tsx`, `components/PreviewModal.tsx`
  - 훅: `hooks/useAppState.ts`(reload·폴링·새 결과 감지), `hooks/useSelection.ts`(toggle/setAll의 Pair 생성을 하나로 통합), `hooks/useColumnResize.ts`
  - `main.tsx`는 `createRoot`만 남긴다.
- 판정 문자열(`일치`, `불일치`, `확인 필요`, `처리 실패`)을 상수로 모은다. JSX는 여러 줄로 정리한다.
- **새 API 계약을 반영한다.** 아래 '공유 API 계약'을 따른다.
  - 목록과 이력 화면은 요약(`/api/results`)을 쓴다.
  - 선택한 결과의 상세는 `/api/results/{id}`로 불러온다. `resultId`가 바뀌거나 새 결과가 생기면 다시 불러온다.
  - 기업 카드를 클릭했을 때 결과를 찾는 로직은 요약의 `mail_ids`를 쓴다.
- **화면 동작과 CSS 클래스는 그대로 유지한다.** `verify_ui.py`가 사용하는 aria-label과 텍스트도 바꾸지 않는다.
- 완료 조건: `npm run build`(tsc 포함) 통과.

### 에이전트 B — 저장·HTTP 계층 (소유: `saebom/store.py`, `saebom/api.py`, 새 파일 `tests/test_store_api.py`)
- **Store에 추가할 메서드**
  - `documents_by_sources(sources) -> dict[source, doc]`: 쿼리 한 번으로 조회한다.
  - `result(id) -> dict|None`
  - `result_summaries()`: `{id, created, parent, count, mismatch, partners(앞 3개), mail_ids}`를 최신순으로 반환한다.
- **`documents.kind` 열 추가**
  - 기존 `disk_path` 마이그레이션과 같은 방식으로 `ALTER TABLE`을 한다.
  - `save_document(..., kind=None)`에 인자를 추가한다.
  - `set_document_root`는 `kind`가 있으면 그 값을 쓰고, 없으면 기존 추측 로직을 그대로 쓴다.
- **`set_document_root` 분해:** 검증, 복사·해시 검증, DB 확정, 이전 파일 정리 헬퍼로 나눈다. 보장 사항(원자성, 롤백, 잠긴 파일 허용)은 그대로 유지한다. 파일명은 `files.safe_name`, 폴더명은 `KIND_FOLDERS`를 쓴다.
- **api.py 변경**
  - `GET /api/results`는 요약 목록을 반환한다.
  - `GET /api/results/{id}`를 신설한다. 상세를 반환하되, 응답에서 각 행의 `invoice/contract/effective_invoice` 안 `extraction.pages`(페이지 전문)는 제거한다. 저장된 데이터는 그대로 둔다.
  - `correct`와 `csv_result`는 `store.result(id)`를 쓴다.
  - 로그인 비밀번호는 `config.APP_PASSWORD`로 비교한다. 실패 횟수 제한은 메모리에서 관리하고, 잠긴 동안에는 HTTP 429와 한글 안내를 반환한다.
  - `state()`의 사이트 URL은 `config.SITE_URL`을 쓰고, 작업 목록은 `service.jobs_snapshot()`으로 가져온다.
  - `settings()`는 `with service.exclusive("저장 위치 변경"):` 안에서 이동한다. 이동하는 동안 `/api/state` 폴링이 막히지 않게 하기 위해서다.
- 새 테스트를 추가한다: 요약·상세 API, `pages` 제거, `result(id)`, 로그인 잠금, `kind` 마이그레이션.

### 에이전트 C — 업무·비교·실행 계층 (소유: `saebom/service.py`, 새 파일 `saebom/jobs.py`·`saebom/site.py`, `saebom/compare.py`, `launcher.py`, 새 파일 `tests/test_service_split.py`)
- **`jobs.py` `JobRunner`:** 작업 상태 복원·저장, `submit`, `update`, `close`, `exclusive(label)` 컨텍스트 매니저를 둔다.
  - `exclusive`는 실행 중인 작업이 있거나 종료 중이면 `ValueError`를 낸다. 이 블록이 실행되는 동안에는 `submit`이 거절된다.
  - 블록 안에서 잠금을 계속 쥐고 있지 않는다.
- **`site.py` `SiteClient`:** 브라우저 수명 관리, `open_mail()`, `fetch_lists()`를 둔다.
  - `fetch_lists()`는 메일과 계약의 행 읽기 JS를 하나의 헬퍼로 통합한다.
  - `fetch_pdf(url) -> bytes`는 `allowed_url`, HTTP 상태, 크기·시그니처를 검사한다.
- **`service.py` `Service`:** `JobRunner`와 `SiteClient`를 조합하는 역할만 한다.
  - 기존 공개 이름을 유지한다: `submit`, `sync`, `open_browser`, `catalog`, `validate_pairs`, `download_one`, `download`, `run_compare`, `close`, `lock`, `jobs`. `scripts/verify_raw_amounts.py`가 `service.jobs`를 쓰므로 `jobs`도 남긴다.
  - `jobs_snapshot()`과 `exclusive()`를 추가한다.
  - 기존 테스트 호환: `test_pdf_cache_path_recovery`가 `service.context`와 `service.browser`를 바꿔치기한다. `download_one`이 이 주입 지점을 그대로 거치게 하거나, 4단계에서 메인이 테스트를 갱신한다.
- **`catalog()`:** `store.documents_by_sources`로 일괄 조회한다. 같은 경로의 파일 존재 확인은 한 번만 한다. 계약은 업체명 정규화 결과로 미리 색인한다. 출력 형태는 기존과 같게 유지한다.
- **`run_compare()`:** 계약별 그룹을 한 번만 만든다(O(n)). `deepcopy`는 `fields`에만 적용한다. 결과 형태와 판정은 그대로 둔다.
- **`download_one()`:** `save_document`에 `kind`를 넘긴다. 이 인자는 에이전트 B가 추가한다.
- **로깅:** 작업 실패와 브라우저 정리 예외를 `logging`으로 남긴다. `except: pass`도 로그를 남기도록 바꾼다.
- **compare.py**
  - `extract`를 `extract_invoice`와 `extract_contract`로 분리한다. `extract`는 진입점으로 남긴다.
  - `check()`에 판정을 직접 받는 `status` 인자를 추가해 `checks[-1]` 덮어쓰기를 없앤다.
  - `OWN_BIZ`와 `MAX_PDF_PAGES`는 config에서 가져온다.
- **launcher.py:** `main()`을 `_existing_instance()`, `_start_server()`, `_run_window()`로 나눈다. `__import__("hashlib")`는 일반 import로 바꾼다.

### 공유 API 계약 (에이전트 A·B가 함께 따름)
```
GET /api/results          → [{id, created, parent|null, count, mismatch, partners:[str], mail_ids:[str]}]
GET /api/results/{id}     → {id, created, parent, rows:[Row...], pairs, overrides}  (extraction.pages 제거)
POST /api/auth/login      → 잠금 중 429 {detail:"…초 후 다시 시도해 주세요."}
```
나머지 엔드포인트와 `/api/state`의 응답 형태는 그대로 유지한다.
