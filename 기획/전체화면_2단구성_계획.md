# 새봄 앱 전체 화면 2단 구성 계획

- 작성일: 2026-10-26
- 근거: 사용자 "모든 면에서는 하나의 화면이 됙 해당 화면과 연결된 링크는 화면을 2단으로 나누어 우측에 정리되어 배치되게 해줘", 대상 확인 "새봄 앱의 모든 화면이야"
- 후속 순서: 앱 화면·기존 문서 검증을 마친 뒤 점검 전용 /check_devdoc_html 커맨드 제작. 커맨드 실행은 파일 수정 금지.

## 1. 화면 규칙

- 로그인 이후 6개 메뉴 모두 왼쪽 업무 본문·오른쪽 관련 링크의 공통 2단 화면으로 구성한다.
- 큰 화면에서는 앱 전체가 한 viewport에 들어오고 본문·관련 링크가 각각 내부 스크롤한다. 긴 목록·표·PDF는 숨기지 않고 접근 가능하게 한다.
- 좁은 화면은 본문→관련 링크 순서로 배치하고 세로로 탐색한다. 가로 넘침이 없게 한다.
- 우측 패널은 현재 화면과 관련된 메뉴 이동·현재 문서의 원문 링크를 구분해서 표시한다. 데이터가 없으면 없는 이유를 안내하고 가짜 링크를 만들지 않는다.
- 새로고침·다운로드·상신 같은 업무 실행은 기존 명시적 버튼으로 유지한다. 관련 링크 클릭에 자동 작업을 연결하지 않는다.
- 인증·모달·판정·데이터 저장 정책·API는 유지한다. 문서 원문 링크는 기존 로컬 API를 사용한다.

## 2. 구현·검증

| 담당 | 소유 |
|---|---|
| 프런트 담당 | frontend/src: 공통 2단 프레임·링크 패널·선택 문서 전달·CSS·코드 주석 |
| 메인 | 기획·검증 스크립트·문서·위키·실제 브라우저 통합 검증 |

1. 기존 CSS 정리 회귀의 동적 시각·경로 차이를 기록하고 증거를 보존한다.
2. 공통 화면 틀과 관련 링크를 추가한다. 메뉴별 내용·선택 상태와 연결한다.
3. 기존 verify_ui·verify_raw_amounts의 문서 전체 스크롤 전제를 내부 스크롤 계약으로 갱신한다.
4. 실제 브라우저에서 1440·1100·760·390px 각 메뉴 표시, 전체 창 가로/세로 넘침, 우측 링크 목적지·문서 파일200, 독립 스크롤·키보드·모달을 확인한다.
5. pytest·빌드·화면 회귀·문서 Mermaid/API/DB/링크를 검증하고 최종 문서와 위키에 새 화면 정책을 반영한다.

이 UI 변경은 승인된 추가 요구이므로 리팩토링 전 PNG와 픽셀 동일을 요구하지 않는다. 변경 전 CSS 회귀 결과와 변경 후 화면검증을 구분해 보관한다. EXE 재빌드·실사이트 상신·커밋·푸시의 별도 확인 범위는 기존과 같다.
