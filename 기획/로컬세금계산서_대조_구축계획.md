# 로컬 세금계산서 대조 기능 구축 계획 (07_auto)

## Context

- 사용자 요청: 로컬 폴더의 세금계산서에서 기업명을 뽑고, 웹(새봄 그룹웨어 `https://sbgw.vercel.app/#/contracts`)의 계약서 목록에서 그 기업의 계약서를 찾아, 계약서 PDF 내용과 세금계산서 내용이 맞는지 확인한다.
  - 화면에는 로컬 폴더의 세금계산서 목록을 보여 주고, 행마다 관련 계약서 유무와 비용 금액 등을 표시한다.
  - 기존 "문서비교" 자산(추출·비교·저장·화면 컴포넌트)을 함께 쓴다.
  - 기능을 완성한 뒤 알고리즘 설명 md를 하나 만든다.
- 사용자 결정 (2026-10-21)
  - **파일 형식**: 그룹웨어 메일 첨부는 PDF와 PNG뿐이고 엑셀은 없다. 그래서 **PDF를 읽는다.** PNG는 목록에만 보이고 '확인 필요'로 둔다(AI·OCR 미사용 원칙).
  - **메뉴 위치**: 사이드바 메뉴 항목 "로컬 세금계산서 대조"를 '계약서 목록' 바로 아래에 둔다.
  - **시험 데이터**: 그룹웨어 메일함의 세금계산서를 내려받아 쓴다("여기에 세금계산서를 다운받아서 해").
- 진행 방식: 07_auto 규칙에 따라 계획을 승인받은 뒤 `기획/로컬세금계산서_대조_구축계획.md`로 저장한다. 모든 새 함수에는 한글 `[기능명세]` 주석을 단다.

## 알고리즘

1. **폴더 읽기**: 사용자가 고른 폴더의 바로 아래 `*.pdf`, `*.png`를 읽는다. 하위 폴더는 읽지 않는다.
   - 최대 200개, 파일 하나당 50MiB 이하만 다룬다.
   - 네트워크 공유(UNC) 경로와 상대경로는 거부한다.
2. **기업명 추출**
   - PDF: `extract(path, "invoice")`의 `partner`(공급자 상호)를 쓴다.
   - 상호가 비었거나 PNG면 파일명 규칙 `세금계산서_{상호}_YYYY-MM`에서 보조로 뽑는다. 이때 출처를 "파일명"으로 표시한다.
3. **웹 계약 찾기**: 대조를 시작하면 `fetch_contracts("전체")`를 한 번 호출한다. 그 결과로 세금계산서마다 다음을 한다.
   - 후보: `norm(계약 거래처)`와 `norm(상호)`가 같거나, 한쪽이 다른 쪽에 들어 있는 계약
   - 우선순위
     1. 지출 계약(매입 세금계산서이므로)
     2. 후보가 여럿이면 계약서 PDF의 사업자번호가 세금계산서 사업자번호와 같은 것
     3. 그래도 여럿이면 청구월이 계약기간 안에 있는 것
   - 결과
     - 후보 0건: "계약서 없음"
     - 후보 2건 이상 남음: "확인 필요". 후보 목록을 보여 준다.
     - 후보가 수입 계약뿐: "확인 필요"
4. **계약서 확보**: `download_one(file, "contract")`로 받는다. 이미 받은 파일은 재사용한다. `save_contract_import(item)`으로 '계약서 목록'에도 남긴다.
5. **판정**: `compare(세금계산서 판독, 계약서 판독)`를 그대로 쓴다. 판정 항목은 사업자번호, 상호, 산술, 세액 10%, 공급가액·세액·합계 기대값, 기간, 지급 조건이다.
   - PNG와 텍스트 없는 PDF는 "확인 필요"로 둔다. 계약 유무와 계약 금액은 그래도 표시한다.
6. **저장**: 마지막 실행 결과를 `meta.local_audit`(JSON)에, 마지막 폴더를 `meta.local_invoice_folder`에 둔다.
   - 결과 행: `file`, `name`, `type`, `invoice{fields}`, `partner_source`, `contract{id, kind, title, period, amount_text}|null`, `contract_doc_id`, `candidates`, `expected{supply, vat, total}`, `status`, `checks`, `note`

## 백엔드 (서브에이전트 A)

- **새 파일 `saebom/local_audit.py`**: 순수 함수 위주로 둔다.
  - `scan_folder(folder) -> [파일 정보와 판독값]`
  - `partner_from_name(filename)`
  - `match_contracts(invoice_row, contracts) -> 후보 목록`
  - `pick_contract(candidates, invoice_fields, contract_docs)`
  - `expected_amounts(contract_fields, month)`: compare의 기대값 계산을 재사용하거나 같은 규칙으로 표시용 값을 만든다.
- **`service.py`**
  - `local_audit_state()`: 폴더, 파일 목록, 마지막 결과
  - `set_local_folder(folder)`
  - `run_local_audit(job)`: 작업 함수. 진행 메시지와 파일별 오류를 남긴다.
- **`api.py`**
  - `GET /api/local-audit`
  - `PUT /api/local-audit/folder` (`{folder}`)
  - `POST /api/local-audit/pick-folder`: 기존 pick_folder 로직을 공용 도우미로 뽑아 쓴다.
  - `POST /api/local-audit/run`: 작업 접수. 작업 이름은 "로컬 세금계산서 대조"
- **`tests/test_local_audit.py`**: 기존 `FakeSite`/`FakeRequest` 방식(`tests/test_contracts_import.py`)과 `tests/fixtures` PDF를 쓴다. 검사할 경우는 다음과 같다.
  - 일치
  - 계약 없음(가온데이터 등 사이트 목록에 없는 거래처)
  - PNG
  - 상호 정규화 매칭
  - 후보 여럿
  - 폴더 검증 거부
  - 결과 저장과 다시 읽기

## 가정 (진행하면서 바꿀 수 있음)

- 엑셀(.xlsx) 세금계산서는 이번 범위에서 뺀다. 예시 파일이 생기면 열 이름 규칙을 추가한다.
- 대조할 때마다 웹 목록을 새로 읽는다. 오프라인 대체는 하지 않고, 실패하면 오류를 표시한다.
- 결과 이력은 마지막 실행 1건만 둔다. 기존 '작업 이력'과는 섞지 않는다.
