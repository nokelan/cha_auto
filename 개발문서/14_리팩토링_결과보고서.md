## 1. 재개 시점과 완료 범위

인수 시점의 R1·R2 구조 개선은 이미 구현돼 있었다. 먼저 pytest119·판정 스냅샷 동일을 직접 확인했다. 서버 R3의 환경변수·죽은 코드 정리도 일부 반영돼 있었으며 이를 확인하고, 누락된 npm 탐색·개발 의존성 분리·외부 구성요소 고지를 보완했다. 프런트는 CSS 분리·토큰·미사용 클래스·중복 반응형 규칙 및 사이트 표시를 마무리했다. 최종 코드를 읽어 전통 형식 개발문서 15개를 작성하고 초안11개를 보관했다.

초기 인계 시 EXE 재빌드는 보류했으나, 후속 사용자 요청으로 R3-5 재빌드·배포본 검증·기존 사용자 데이터로 재실행까지 완료했다(8절). 실사이트 검사·상신·커밋·푸시는 수행하지 않았다.

## 4. 의도된 동작 차이와 유지 정책

월 0000-05는 공용 월 검증에서 바로 거절한다. 거래명세서 셀은 기존 수식 접두어에 더해 탭·캐리지 리턴도 이스케이프한다. 총액 계약 period의 확인 필요는 유지한다. 비교 norm 통합·판정 정책 변경은 하지 않았다. 상신 시작 때 이전 완료 상태 초기화도 유지한다.

## 7. 추가 요청 — 앱 전체 한 화면·2단 배치

사용자는 "새봄 앱의 모든 화면이야"라고 적용 대상을 확인했다. 이에 로그인 후6개 메뉴 모두 왼쪽 업무·오른쪽 관련 링크 공통 프레임으로 변경했다. 한 viewport 안에서 두 영역이 독립 스크롤하며 760px 이하에서는 본문 위·링크 아래로 배치한다. 관련메뉴·선택 원문·현재 결과CSV·설정의 사이트 링크를 표시하며, 업무 실행 버튼은 기존 본문에 둔다. 관련 링크 이동 자체는 상신·동기화 같은 작업을 실행하지 않는다.

구현: frontend/src/components/RelatedLinks.tsx, styles/workspace-layout.css, App 및 계약·로컬 화면의 선택문서 콜백. 승인 계획은 [전체화면 2단 구성](../기획/전체화면_2단구성_계획.md). 이 추가 UI 요청은 동작 불변 리팩토링과 구분해 보고하며 변경 전 PNG와의 픽셀 동일을 요구하지 않는다. 화면·요구사항 문서와 실제 휠 검증도 새 스크롤 계약으로 갱신했다.

## 8. R3-5 배포 완료

2026-10-26 사용자 후속 요청으로 EXE/ZIP을 재빌드하고 scripts/verify_release.py로 실제 배포본 검증5종을 모두 통과했다. 정적자산202개·템플릿 해시 일치, 배포2056파일/ZIP목록·크기 일치와 CRC를 확인했다. 운영DB 백업 후 새 EXE를 실행하고 기존6테이블의 업무행·설정 보존 및 health/state/results200을 확인했다. 사용자가 "잘 실행되었어"라고 확인했다.

검증·적용 증거: tmp/exe-release-review/20261026-111042/validation/report.json 및 activation.json. 이전 ZIP·운영DB 백업도 같은 폴더에 보관했다. 실행파일은 dist/SaebomCompare/SaebomCompare.exe, 배포ZIP은 dist/SaebomCompare-Windows.zip이다. 실제 사이트 상신은 미실행이다.
