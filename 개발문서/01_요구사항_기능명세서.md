# 요구사항·기능명세서

- 기준일: 2026-10-26
- 기준: 리팩토링 1~3단계 최종 소스. 실제 수행한 검증 범위는 [테스트 명세서](11_테스트_명세서.md)와 [리팩토링 결과보고서](14_리팩토링_결과보고서.md)를 참조한다.
- 제품: 새봄 문서비교. Windows PC에서 FastAPI·React·SQLite·Playwright로 운영하는 로컬 앱.
- 업무 대상: 그룹웨어의 세금계산서·계약서, 로컬 세금계산서, 수입 계약 거래명세서, 지출 계약 지출결의서.

## 1. 목적·범위

사람이 PDF 원문과 추출 근거를 보고 계약 금액·기간·지급 조건을 확인하도록 돕는다. 판독·판정·입력·상신은 정규식·계산식·DOM 자동화 스크립트로 처리하며 AI API·OCR을 사용하지 않는다. 저장 문서의 비교와 원문 조회는 로컬에서 수행한다. 사이트 목록 수집·다운로드·상신은 인터넷 접속이 필요하다.

일반 사용자는 실행 세션과 시작 비밀번호를 통과한 단일 로컬 사용자다. 그룹웨어 계정이 필요하면 앱 전용 브라우저에서 직접 로그인한다. 다중 사용자·서버 배포·전자결재 승인 자체·OCR은 현재 범위에 없다.

## 3. 입력·출력과 예외 조건

| 기능 | 입력 제한·선행조건 | 정상 산출 | 실패·미확정 처리 |
|---|---|---|---|
| 비교·다운로드 | 연결 1~500건; 서버가 저장 목록과 첨부 URL 소속 확인 | 작업 ID, 상태 폴링 후 문서·비교 결과 | 잘못된 연결 거절; 파일별 오류는 작업 오류 목록 |
| 계약 가져오기 | 전체/수입/지출; 개수 빈 값 또는 1~500; 새 계약 조건 | PDF 저장 성공한 계약의 가져오기 기록 | 전체 목록이 비면 전용 브라우저 로그인 확인 오류; 구분 목록이 빈 것은 정상 |
| 거래명세서 | 수입 계약·원문; 유효한 날짜·월·품목·금액; 출력 최대 12줄 | PDF 루트 아래 `거래명세서/`의 새 xlsx | 지출 계약·원문 없음·기간/금액/줄 수 오류 거절; 기존 파일 덮어쓰지 않음 |
| 로컬 대조 | 존재하는 PC 절대 폴더; UNC 미지원 | 마지막 대조 결과·상태 집계·후보·원문 연결 | PNG·이미지 PDF는 확인 필요; 후보 없음/복수는 별도 안내 |
| 지출결의서 | 지출 계약·원문; 월·제목·금액 검산 | 사이트 기안, 검토 항목, 계약 품의 상태 | 상신 후 오류·검토 불일치 때 상태 없음과 `site_draft` 경고 |
| 저장 위치 | 로컬 절대경로; 다른 작업과 배타 실행 | 종류별 PDF 복사·DB 경로 변경·이전 사본 정리 | 복사/검사 실패 시 새 복사본 정리, DB 변경 전 중단 |

## 4. 판정 정책

근거: `saebom/compare.py:186`의 `compare()`와 동일 파일 `extract()`.

1. 텍스트 추출 불가 문서는 **확인 필요**, 그 밖의 문서 처리 오류는 **처리 실패**다. 누락값을 0이나 일치로 채우지 않는다.
2. 정상 추출 문서는 사업자번호·업체명·공급가액·세액·합계·기간·지급 조건을 검사한다. 종합 상태는 **불일치 > 확인 필요 > 일치** 우선순위다.
3. 월액 계약은 청구 월 전체가 계약기간 안에 있는지 확인한다. 발행일을 청구 월로 대신하지 않는다. 지급 조건 일치는 실제 지급 사실을 뜻하지 않는다.
4. 총액 계약은 계약에 명시된 분할 비율과 청구 비율을 확인한다. 허용 비율을 확정하지 못하면 계약 금액을 임의 계산하지 않는다.
5. **총액 계약의 `period`(분할 지급 조건)는 항상 확인 필요다.** 납품·설치·검수의 실제 이행은 PDF만으로 확정할 수 없다는 의도된 정책이며 버그가 아니다. 다른 항목이 모두 일치해도 종합 상태에 반영된다(`compare.py:240`).
6. 세액은 `Decimal`의 원 단위 사사오입(`ROUND_HALF_UP`)을 쓴다. 총액×청구 비율 직후 `int` 변환의 절삭은 기존 정책을 유지한다.
7. 원 추출값은 보정값과 별도로 표시한다. 보정은 새 결과에 적용되며 기존 이력을 덮어쓰지 않는다.

## 5. 상신 상태 정책

근거: `saebom/services/contracts_service.py:171`.

| 사건 | 로컬 상태 | 보조 데이터·사용자 행동 |
|---|---|---|
| 입력 검증·접수 실패 | 이전 상태 유지 | 오류 수정 후 재시도 |
| 상신 작업 시작 | 없음 | 이전 성공을 새 성공으로 오인하지 않도록 초기화 |
| 작성본 검토 전 항목 일치 | 품의완료 | 문서번호·URL·검토 기록 저장 |
| 작성본 검토 불일치 | 없음 | `site_draft=true`; 사이트 기안 확인 후 재상신 판단 |
| 상신 클릭 이후 불확실 오류 | 없음 | `site_draft=true`, 오류 저장; 자동 재상신하지 않음 |
| 상신 클릭 이전 오류 | 없음 | 오류 저장; 사이트 기안 플래그는 설정하지 않음 |

`품의완료`는 이 앱이 상신 후 작성본을 대조한 로컬 상태다. 그룹웨어의 최종 결재 승인 상태와 동의어가 아니다. 같은 청구 월의 완료 기록은 중복 경고에 쓰며 중복 방지의 유일성 제약은 아니다. 상신 시작 때 상태를 `없음`으로 초기화해도 이전 완료 기록은 `prior_approval`로 보존해 같은 달 중복 경고가 사라지지 않게 한다(2026-10-26). 사이트 작성본을 받은 뒤 검토·저장에서 예외가 나면 `site_draft=true`와 문서번호·URL·오류를 남긴다.

## 6. 비기능 요구·한계

| ID | 요구·현 구현 |
|---|---|
| N-01 | 서버는 loopback에서 실행하며 실행 쿠키와 비밀번호 쿠키로 업무 API를 보호한다. |
| N-02 | PDF 한 건 50MiB, 자동 판독 100페이지, 비교 연결 500건 제한. 다운로드 URL은 고정 사이트 HTTPS PDF만 허용한다. |
| N-03 | 주요 작업은 단일 작업 스레드에서 실행하며 다른 작업 접수를 거절한다. 재시작 시 이전 running은 failed로 복원한다. |
| N-04 | 화면은 작업 중 1초·유휴 8초 폴링, 한 viewport 안의 본문/관련 링크 독립 스크롤, 모바일 위아래 배치, 키보드 접근 가능한 공용 모달을 제공한다. |
| N-05 | 저장 문서·SQLite·전용 브라우저 프로필은 로컬에 남는다. 데이터 암호화·다중 사용자 권한 모델은 구현하지 않았다. |
| N-06 | 전체 작업의 제한시간·강제 취소는 없다. 결과 JSON 내부 문서 사본 중복, 절대경로 이관, 로그인 전역 잠금·감쇠 없음은 후속 개선 과제다. |

## 7. 인수 조건·참조

기능별 승인 근거는 단위검사, 판정 스냅샷, 프런트 빌드, 격리 데이터의 화면 회귀 검증으로 구분한다. 실제 사이트·사용자 DB 변경·EXE 재배포 여부는 각 결과보고서에 따로 적는다. 테스트 대역이 통과했다고 실제 사이트 상신 성공으로 보고하지 않는다.
