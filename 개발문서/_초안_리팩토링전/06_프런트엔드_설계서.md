## 2. 화면(메뉴) 목록

라우터가 없다. 화면 전환은 `App`의 `screen` 상태 문자열(`App.tsx:59`)을 사이드바 버튼이 바꾸는 방식이고(`App.tsx:322`), URL·히스토리는 바뀌지 않는다. 화면은 조건부 렌더링(`App.tsx:388-431`)이라 화면을 벗어나면 그 화면 컴포넌트는 언마운트된다. 메뉴 정의는 `NAV`(`App.tsx:30-37`), 제목·설명은 `HEADINGS`(`App.tsx:40-47`)다.

### 4.2 `useAppState` 폴링

| 항목 | 값 |
|---|---|
| 조회 대상 | `GET state` + `GET results`(요약 목록)를 `Promise.all`로 함께(`useAppState.ts:76`) |
| 최초 | 마운트 시 `reload()` 1회(`:94`) |
| 주기 | 진행 중 작업(`state.jobs`에 `status==='running'`)이 있으면 1000ms, 없으면 8000ms(`:104-108`). `setInterval`이며 `running`·`stopped` 변경 시 재생성 |
| 중단 조건 | `stopped`가 true면 타이머를 만들지 않음 |
| 결과 상세 | `targetId`(선택한 결과 ID가 요약에 있으면 그것, 아니면 최신 요약)가 바뀔 때만 `GET results/{id}`(`:120-141`). 폴링마다 다시 받지 않음. 응답이 늦게 도착하면 `cancelled`로 무시 |
| 상세 실패 재시도 | 실패하면 `detailFailed`를 세우고 다음 `results` 갱신(폴링) 때 `retryTick`을 올려 다시 요청(`:149-155`) |
| 오류 문구 | `error`(폴링 실패, 다음 성공 시 지움)와 `detailError`(상세 실패, 상세 성공 또는 사용자가 닫을 때까지 유지)를 분리하고 `error \|\| detailError`로 반환 |
| 새 완료 결과 선택 | 아래 4.5절 |

### 4.4 화면 이동 시 상태 유지/초기화

화면 컴포넌트가 조건부 렌더링이라(`App.tsx:388-431`) 화면 내부 `useState`는 메뉴를 옮기면 사라진다. App·훅에 있는 상태는 유지된다.

| 상태 | 위치 | 메뉴 이동 시 | 새로고침(F5) 시 |
|---|---|---|---|
| 선택한 메일·연결 계약, 검색어·날짜, 단 너비 | App·훅 | 유지 | 초기화(저장 안 함) |
| 선택한 결과 ID, 행 번호, 포커스 메일 | App·`useAppState` | 유지 | 초기화(최신 결과로 복귀) |
| 원문 미리보기·보정 모달·보정 입력값 | App | 유지(모달은 화면 밖에 렌더) | 초기화 |

### 8.4 TSX와 대조한 미사용·미정의 클래스

## 11. 화면(메뉴) 추가 절차

현재 코드 구조에서 새 메뉴를 추가하려면 다음을 고친다.

1. `screens/<영역>/NewScreen.tsx`를 만든다. 서버 데이터는 `props`로 받거나(`state`, `jobs`) 자체 `api()`로 조회하며, 서버 작업을 실행하려면 부모의 `act`를 `onRun` 같은 콜백으로 받는다(`LocalAuditScreen`·`ContractsScreen` 방식).
2. `App.tsx`의 `NAV`(`:30-37`)에 `{id, label, icon}`을 추가한다. 아이콘은 `lucide-react`에서 import한다.
3. `HEADINGS`(`:40-47`)에 제목·설명을 추가한다. 없으면 `settings` 문구가 표시된다(`:92`).
4. `App.tsx` 렌더 영역(`:388-431`)에 `{screen === 'new' && <NewScreen …/>}`를 추가한다.
5. 서버 작업이 있으면 `useAppState`의 새 결과 감지(`:163`)가 필요한지 판단한다. 계약서·로컬 대조처럼 자체 목록을 갱신해야 하면 화면 안에 `seenJobs` 패턴(4.5절)을 복제하고 감시할 `kind` 문자열을 서버 `service.submit`의 이름과 맞춘다.
6. 새 서버 응답 형태는 `types.ts`에 추가한다.
7. 새 모달은 `ExpenseModal`의 구조(포털, `role=dialog`, 포커스 트랩, 스크롤 잠금, 포커스 복귀)를 따르고 닫기 버튼 `aria-label`을 지정한다.
8. 스타일은 `style.css` 구역 주석 패턴에 맞춰 추가하고 `max-width:1024px`·`600px` 규칙을 함께 점검한다. 새 화면 전용 CSS가 많으면 `contracts.css`처럼 화면 폴더에 두고 import한다.
9. 검증은 `scripts/verify_*.py` 패턴으로 접근성 이름 또는 `data-testid`를 쓴다.
10. 파일마다 `[파일 역할]`과 함수별 `[기능명세]`를 한글로 작성하고, 관련 문서(`프로그램_기술설계서.md` 3.3절 파일표, 이 문서 2절)를 갱신한다.
