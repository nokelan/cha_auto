## 2. 자동화 방식

### 2.1 두 개의 Playwright 브라우저

| 구분 | 앱 화면용 | 그룹웨어 자동화용 |
|---|---|---|
| 코드 | `launcher.py:106-132`(`_run_window`) | `site.py:87-103`(`SiteClient.page`) |
| 스레드 | 별도 데몬 스레드(`launcher.py:166`) | 작업 스레드 `site-worker`(`jobs.py:38`, `ThreadPoolExecutor(max_workers=1)`) |
| 프로필 폴더 | `{데이터 폴더}/app-profile` (`launcher.py:117`) | `{데이터 폴더}/browser-profile` (`core.py:17`) |
| 대상 | `http://127.0.0.1:{port}/?token=…` | `SITE_URL` |
| 표시 | `headless=False`, `no_viewport=True`, `--app=` 주소창 없는 창, `--window-size=1440,960`, `--enable-automation` 인자 제외 | `headless=False`, 뷰포트 `1280×860`, `accept_downloads=True` |
| 수명 | 앱 창이 닫히면 서버 종료(`launcher.py:122`, `:136`) | 첫 사이트 작업에서 늦게 생성, 이후 재사용, 종료 시 정리(`Service.close`) |

- 데이터 폴더는 기본 `%LOCALAPPDATA%\SaebomCompare`이고 환경변수 `SAEBOM_DATA_DIR`로 바꿀 수 있다(`store.py:50`).
- `SAEBOM_NO_OPEN=1`은 **앱 화면용** 창만 막는다(`launcher.py:109`). 사이트 자동화용 브라우저는 이 값과 무관하게 항상 `headless=False`이므로 검증 스크립트가 서버를 띄워도 사이트 작업 때 창이 뜬다.
- 사이트 브라우저에 `--app`이나 자동화 숨김 인자는 쓰지 않는다(`site.py:100`).

### 2.2 `SiteClient.page()` 수명 규칙 (`site.py:87-103`)

1. `context`가 있고 `context.pages` 접근이 되며 `page_obj`가 닫히지 않았으면 기존 페이지를 재사용한다.
2. 위가 실패하거나 페이지가 닫혔으면 `close()`로 정리한 뒤(`:95`) 새로 만든다. 사용자가 사이트 창을 닫아도 다음 작업에서 다시 열린다. 판정 중 예외는 debug 로그만 남는다.
3. 번들 Chromium 경로: `Path(sys._MEIPASS 또는 저장소 루트) / "browser"`가 있으면 `os.environ["PLAYWRIGHT_BROWSERS_PATH"]`를 그 폴더로 설정한다(`:96-98`). 배포 시 `scripts/build.py:39`가 `--add-data {chromium 폴더};browser/{폴더명}`로 포함하므로 EXE 안에서는 번들이 우선이고, 개발 환경에서 `browser/` 폴더가 없으면 Playwright 기본 설치 위치를 쓴다. 앱 화면용도 같은 규칙이다(`launcher.py:112-114`, 루트는 `_MEIPASS` 또는 `launcher.py`가 있는 폴더).
4. `sync_playwright().start()` → `chromium.launch_persistent_context(프로필, headless=False, accept_downloads=True, viewport 1280×860)` → `set_default_timeout(15000)` → 기존 첫 탭 재사용 또는 새 탭(`:99-102`).

### 2.3 단일 작업 스레드 전제

- Playwright 동기 API 객체는 만든 스레드에서만 써야 한다. `SiteClient`의 모든 메서드는 `Service.submit`으로 예약한 작업 스레드(`site-worker`, 워커 1개)에서만 호출한다(`site.py:66-67` 주석, `jobs.py:38`). 종료 정리도 같은 스레드에 예약한다(`JobRunner.close(cleanup)`, `jobs.py:148-152`).
- 작업은 동시에 하나만 실행된다. 실행 중이거나 배타 구간 중이면 새 작업은 `ValueError('현재 작업이 끝난 뒤 실행해 주세요.')`로 거절된다(`jobs.py:81-84`).
- 사이트 작업에는 작업 전체 제한시간이 없다. 한 작업이 멈추면(무한 대기) 이후 작업이 모두 거절된다(아래 6절 참고).

### 3.3 기대하는 텍스트 형식 (작성본 검토, `expense.py`)

`SiteClient`가 읽은 문자열을 `expense.parse_document`(`expense.py:90-102`)가 정규식으로 해석한다. 패턴이 안 맞으면 해당 값은 `None`이고 검토 항목은 불일치가 된다(`expense.py:122`, `ok`는 `actual is not None`을 요구).

| 읽는 값 | 기대 형식(정규식 요지) | 위치 |
|---|---|---|
| 금액 칸 `doc-amount` | `KRW 2,310,000` 전체 일치(`fullmatch`) | `expense.py:93` |
| 본문 합계·공급가액·세액 | `금 액 : 2,310,000원 (공급가액 2,100,000원 / 세액 210,000원)` (공백 유연, 전각 콜론 허용) | `:92` |
| 업체명 | `업 체 명 : …`, 줄 끝의 `(000-00-00000)` 사업자번호는 제거 | `:94`, `:96` |
| 사용 월 | `사용기간 : 26.09` 또는 `26년 09월` 또는 `2026.09` 형식(두 자리/네 자리 연도) | `:95` |
| 제목 | `doc-title` 텍스트(공백 정리 없이 비교) | `:120` |

검토 8항목은 작성본 금액, 본문 합계, 본문 공급가액, 본문 세액, 공급가액+세액=합계, 업체명, 사용기간, 제목이며 모두 일치해야 `품의완료`다(`expense.py:113-120`, `contracts_service.py:174-175`). 업체명만 법인 표기·공백을 정규화(`norm`)해 비교하고 나머지는 정확히 같아야 한다.

## 4. PDF 다운로드 규약

`SiteClient`가 아니라 모듈 함수 `allowed_url`, `read_pdf_response`, `request_pdf`(`site.py:30-63`)가 담당한다. 호출은 `Service.download_one`(`core.py:170-189`)이 한다.

| 단계 | 규칙 | 위반 시 |
|---|---|---|
| 캐시 | 같은 원본 URL의 문서가 DB에 있고 파일이 존재하면 사이트에 접속하지 않고 재사용(`core.py:172-174`) | - |
| URL 검사 (`allowed_url`, `site.py:30-34`) | 스킴 `https`, `netloc`이 `SITE_HOST`와 **정확히 같음**(포트·사용자정보가 있으면 불일치), 경로(소문자)가 `.pdf`로 끝남. 쿼리 문자열은 검사하지 않음 | `ValueError('대상 사이트의 PDF 다운로드 링크만 사용할 수 있습니다.')` |
| 요청 (`request_pdf`, `:62`) | `context.request.get(url, timeout=30000, max_redirects=0)`. 로그인 쿠키·프로필 쿠키를 공유한다 | 네트워크 오류는 Playwright 예외 전파 |
| 리다이렉트 | 따라가지 않는다(`max_redirects=0`). 3xx 응답은 상태 200이 아니므로 아래 상태 검사에서 거절 | `ValueError('다운로드 HTTP 302: {이름}')` 형식 |
| 상태 | HTTP 200만 허용(`read_pdf_response`, `:45-46`) | `ValueError('다운로드 HTTP {상태}: {이름}')` |
| 크기·형식 | 본문 전체를 읽은 뒤 `len(body) <= MAX_PDF_BYTES`(50MiB, `config.py:20`)이고 앞 공백 제거 후 `%PDF-`로 시작 | `ValueError('PDF 형식이 아니거나 파일이 50MB를 초과합니다.')` |
| 저장 | SHA-256 → `{문서 저장 폴더}/세금계산서 또는 계약서/{해시 앞 12자}_{안전한 이름}`에 `.part`로 쓴 뒤 교체(`core.py:179-186`). 기존 파일이 있으면 덮어쓰지 않음 | - |
| 판독 | `extract(path, kind)` 후 `save_document` | 판독 오류는 문서 레코드에 기록 |

크기 상한은 응답 본문을 받은 뒤 검사하므로 스트리밍 중 차단은 없다(기존 문서 7절에도 기재). 페이지 수 한도(`MAX_PDF_PAGES`, `config.py:21`)는 판독 단계 규칙이며 사이트 연동 규약이 아니다.

### 5.2 성공·오류 판정 (사이트 쪽)

| 상황 | 판정 방법 | 앱 동작 |
|---|---|---|
| 성공 | `location.hash`가 `#/doc/`로 시작 | 작성본에서 제목·금액·본문·문서번호를 읽고 서버 검토로 진행 |
| 사이트가 거절(폼 오류) | `[data-testid="form-error"]:not([hidden])` 표시 | `ValueError('사이트 상신 오류: {사이트 문구}')` → 작업 `failed`, 계약 상태 `없음`+`error` 저장 |
| 30초 안에 둘 다 안 일어남 | `wait_for_function` 시간 초과 | `TimeoutError` → `failed`. 상신은 이미 눌렸으므로 기안이 만들어졌을 수 있으나 앱은 알 수 없음 |
| 작성본 일부 텍스트 형식 불일치 | 3.3절 정규식 실패 | 해당 검토 항목 `ok=false` → 상태 `없음`(실패가 아닌 "작성본 검토 불일치") |

상신 후 오류가 나도 자동 재상신하지 않는다(`site.py:194` 주석, `contracts_service.py:159`). 같은 청구월에 `품의완료` 기록이 있어도 재상신 자체는 허용되고 경고만 표시한다(`contracts_service.py:149-152`, `ExpenseModal.tsx:66`, `:202`).

### 5.3 기안이 남는 곳

- 코드 주석은 "전용 브라우저 localStorage에 기안 저장"이라고 적는다(`site.py:195`, 화면 안내 `ExpenseModal.tsx:239`, 기획 문서의 `app.js` 조사 결과). 이 저장소에는 사이트 소스가 없어 직접 확인할 수 없고, 사이트 서버 DB에 남지 않고 `browser-profile`의 localStorage에만 남는다는 서술은 이 주석과 기획 문서에 근거한 것이다(추정).
- 따라서 앱의 전용 브라우저가 아닌 다른 브라우저·프로필에서는 작성본(`doc_url`)이 보이지 않을 수 있다. 프로필 폴더를 지우면 기안도 사라진다.
- 앱 DB에는 상신 결과(`doc_id`, `doc_no`, `doc_url`, `review`, `warnings`, 상태)만 `contract_status`로 저장된다.
- 첨부는 파일을 업로드하지 않고 사이트가 이미 가진 첨부 후보 체크박스를 이름으로 선택할 뿐이다(`site.py:208-214`).

## 9. 데이터 반출·쓰기 범위

### 9.1 사이트에 쓰는 동작은 상신뿐인가

`saebom/*.py`, `saebom/services/*.py`, `launcher.py`에서 사이트 조작 호출(`.click(`, `.fill(`, `.check(`, `select_option`, `.goto(`, `request.post`, `evaluate`, `localStorage`)을 grep한 결과는 다음과 같다.

| 호출 | 위치 | 성격 |
|---|---|---|
| `goto(…#/mail)`, `goto(…#/contracts)`, `goto(…#/draft)` | `site.py:134`, `:178`, `:198` | 이동(읽기) |
| 링크 `계약 문서함` `click()` | `site.py:176` | 이동(읽기) |
| `#contract-filter`.`select_option(label=kind)` | `site.py:180` | 화면의 필터 컨트롤 변경. 사이트 데이터를 바꾸지 않는 화면 상태 변경(필터 값이 사이트에 저장되는지는 확인 불가, 추정: 저장 안 됨) |
| `#f-form`, `#f-contract` `select_option`, 입력칸 `fill`, 첨부 `check`, `submit` `click` | `site.py:203-215` | **쓰기(상신)**. 사이트에 새 기안이 만들어짐 |
| `context.request.get(url, …)` | `site.py:62` | HTTP GET(읽기). `post`·`put`·`delete` 호출은 없다 |
| `evaluate_all(ROWS_JS)`, `evaluate_all("xs => xs.map(x => x.value)")` | `site.py:146`, `:200`, `:208` | DOM 읽기 |

결론: 사이트에 값을 **쓰는** 코드 경로는 `submit_expense`(지출결의서 상신) 하나뿐이다. 수입결의서·품의서 양식 선택, 기안 수정·삭제·회수, 첨부 업로드 코드는 없다. `localStorage`를 코드가 직접 읽거나 쓰지 않고(`site.py:195` 주석에서만 언급), 쿠키 조작·네트워크 요청 가로채기·스크립트 주입도 없다.

### 9.2 데이터 흐름

| 방향 | 내용 | 저장·전송 위치 |
|---|---|---|
| 사이트 → 앱 | 메일(발신자·제목·수신일·첨부 이름·URL), 계약 7열 표, PDF 파일 | 앱 DB와 PC의 원본 PDF 폴더(`store.snapshot`, `save_document`, `save_contract_import`) |

AI·OCR 서비스 호출은 없다(위 grep 기준). 사이트 접속은 위 1.3절 기능에서만 일어나고 저장된 PDF의 비교·조회·CSV는 오프라인이다.
