# 새봄 문서비교 백엔드 상세설계서

- 작성일: 2026-10-26
- 대상: `saebom/` 패키지와 `launcher.py`를 수정하거나 새 기능(작업·API)을 추가하는 백엔드 개발자
- 문서 기준: `saebom/**/*.py` 24개 파일과 `launcher.py`를 2026-10-26에 직접 읽은 결과. `secrets.compare_digest`의 비ASCII 입력 동작과 `Store`의 SQLite 동작은 임시 DB·인터프리터로 실행해 확인했다. 확인하지 못한 내용은 "(추정)"으로 표시했다.
- 관련 문서: [기술설계서](../프로그램_기술설계서.md)(8절 PDF 추출, 9절 비교 규칙, 12절 저장 위치 이동, 13절 작업·동시성, 14절 API), [04_데이터설계서](04_데이터설계서.md), [로컬세금계산서 대조 알고리즘](../로컬세금계산서_대조_알고리즘.md), [AI 없이 텍스트 수집·PDF 다운로드 동작원리](../AI없이_텍스트수집_PDF다운로드_동작원리.md)

기술설계서는 "무엇을 어떤 규칙으로 판정하는가"를 설명한다. 이 문서는 "어느 파일의 어느 함수가 어떤 순서로 호출되고, 어떤 예외가 어디서 HTTP 응답이나 작업 실패로 바뀌는가"를 함수 단위로 정리한다. 테이블·JSON 구조는 [04_데이터설계서](04_데이터설계서.md)에 있으므로 여기서는 링크로 대신한다.

## 3. 믹스인 구조

### 3.1 조합과 해석 순서

`class Service(Core, CompareMixin, ContractsMixin, LocalAuditMixin)`(`saebom/service.py:9`)이며 본문은 `pass`다. `service.py`는 `from .services.common import *`로 공용 이름을 다시 내보내므로 `saebom.service.extract`, `saebom.service.Store` 같은 옛 import 경로가 계속 동작한다(`saebom/service.py:2`). 이름이 겹치는 메서드는 없다(각 믹스인의 메서드 이름이 서로 다름, 1.9절 표로 확인).

믹스인은 자기 `__init__`이 없고, `Core.__init__`이 만든 속성과 `Core`의 메서드를 `self`로 사용한다. 믹스인만 따로 인스턴스화할 수 없다.

### 3.2 믹스인이 기대하는 `self.*`

| 믹스인 | 읽는 `self.*` 속성 | 호출하는 `self.*` 메서드 |
|---|---|---|
| `Core` | (자기가 만듦) `store`, `runner`, `site`, `_invoice_cache`, `_invoice_cache_lock` | `browser`, `update`, `submit`, `_doc_path` 등 자기 메서드 |
| `CompareMixin` | `store`, `site`, `closing` | `browser`, `update`, `download_one`, `_doc_path`, `validate_pairs`(`download`·`run_compare` 안) |
| `ContractsMixin` | `store`, `site`, `closing` | `update`, `download_one`, `_doc_path`, `exclusive`, `submit`, `run_expense`(`submit_expense`가 메서드 객체로 전달), `statement_folder`, `_statement_source`, `expense_draft` |
| `LocalAuditMixin` | `store`, `site`, `closing`, `_invoice_cache`, `_invoice_cache_lock` | `update`, `download_one`, `_doc_path` |

`Core`가 `lock`·`jobs`·`closing`·`context` 속성을 `JobRunner`·`SiteClient`에 위임하는 이유는 기존 호출자(`api`, `scripts/verify_raw_amounts.py`, 테스트) 호환이다(`saebom/services/core.py:22-26`).

`from .common import *` 방식이므로 `common.py`가 import하는 이름(`copy`, `hashlib`, `re`, `threading`, `Path`, `local_audit`, `statement`, `compare`, `extract`, `norm`, `MAX_PAIRS`, `SITE_URL`, `KIND_FOLDERS`, `STATEMENT_FOLDER`, `safe_name`, `JobRunner`, `SiteClient`, `allowed_url`, `check_lists`, `request_pdf`, `Store`, `now`)이 모든 믹스인 파일의 전역이 된다(`saebom/services/common.py:12-24`). `__all__`이 없으므로 밑줄로 시작하지 않는 이름이 전부 내보내진다. 믹스인 파일에서 새 외부 모듈을 쓰려면 `common.py`에 import를 추가하거나 `contracts_service.py:3`처럼 파일 안에서 import한다.

| 그 외 예외(작업 스레드) | 사이트 DOM 변경, Playwright 타임아웃, `KeyError` 등 | 같은 `except Exception`이 `failed`로 기록하고 `log.exception`으로 `app.log`에 남김 |
| `LookupError` | `_statement_source`(`contracts_service.py:88`) | 네 핸들러(`expense_draft`, `submit_expense`, `statement_draft`, `create_statement`)가 각자 `try/except`로 **HTTP 404** `가져온 계약을 찾을 수 없습니다.`로 변환(`routes/contracts.py:22,33,72,87`). 다른 곳에서 던지면 처리되지 않음 |
| `HTTPException(404)` | 결과·문서·거래명세서 파일 없음 | `routes/compare.py:79,94,128`, `routes/system.py:84`, `routes/contracts.py:100-109` |
| `HTTPException(429)`, `(401)` | `login` 잠금 중, 비밀번호 오류 | `api.py:177,183` |

| `json.JSONDecodeError`, `pydantic.ValidationError` | DB의 손상 JSON 읽기 등 | 둘 다 `ValueError`의 하위 클래스라 핸들러 스레드에서는 **400**이 된다(코드 구조에 따른 결과이며 실제 손상 DB로 재현하지 않음, 추정) |

작업 실패와 파일별 오류는 구분된다. 일부 파일만 실패한 경우 `errors`에 파일별 문구가 쌓이고, 마지막에 `ValueError`를 던져 작업 전체를 `failed`로 표시한다(`download`, `import_contracts`). `run_local_audit`은 행 단위 실패를 `처리 실패` 행으로 남기고 작업은 정상 완료로 끝낸다(`errors`만 채움).

## 6. 확장 가이드

현재 구조에서 새 기능(작업·API·화면)을 추가하는 절차다. 프로젝트 규칙에 따라 새 소스와 함수에는 한글 주석과 기능명세를 함께 쓴다(`CLAUDE.md`).

### 6.1 새 기능 추가 절차

1. **규칙을 순수 함수로 분리한다.** DB·네트워크를 쓰지 않는 규칙은 `saebom/<기능>.py`로 둔다(`local_audit.py`, `statement.py`, `expense.py`가 같은 방식). 입력은 문서 사전·계약 행, 출력은 JSON 직렬화 가능한 사전으로 한다.
2. **서비스 메서드를 적절한 믹스인에 추가한다.** 이미 있는 영역이면 해당 믹스인(`services/*_service.py`)에, 새 영역이면 새 믹스인 클래스를 만들고 `service.py:9`의 상속 목록과 import에 추가한다. 믹스인에서 쓰는 외부 이름은 `common.py`에서 가져오거나 파일에서 직접 import한다(3.2절).
3. **오래 걸리는 일이면 작업으로 만든다.** 메서드 시그니처를 `def run_x(self, job, ...)`로 하고 다음 규칙을 지킨다.
   - 진행은 `self.update(job, total=…, done=…, message=…, errors=…)`로 알린다.
   - 반복문마다 `if self.closing:`을 확인하고 종료 요청이면 `ValueError`를 던진다(`download` 패턴).
   - 성공 메시지는 문자열로 반환하면 작업 메시지가 된다. 일부 실패는 `errors`에 모았다가 마지막에 `ValueError`로 실패 처리한다.
   - 사이트 접속은 반드시 작업 스레드 안에서만 한다(Playwright sync API 제약).
   - 결과 ID가 필요하면 `self.update(job, result_id=…)`처럼 필드를 더한다(화면이 읽는 필드는 프런트의 작업 타입과 맞춘다).
4. **DB에 저장할 것이 있으면** 한 번뿐인 설정·마지막 결과는 `meta_set`/`meta_get` JSON 키로(키 상수는 `common.py:31-32`처럼 둔다), 목록은 새 테이블로 정한다. 새 테이블·열은 [04_데이터설계서 6절](04_데이터설계서.md)의 절차를 따른다.
5. **요청 모델을 `api_models.py`에 추가한다.** 길이·범위는 `Field`로, 금액은 `StrictInt`로 제한한다(구조 오류는 422, 업무 규칙은 서비스에서 `ValueError`→400).
6. **경로를 등록한다.** 기존 모듈의 `register`에 핸들러를 더하거나, 새 모듈을 `routes/`에 만들고 `api.py:189-194`의 import와 `for routes in (...)` 튜플에 추가한다. 핸들러는 동기 `def`로 쓰고 긴 일은 `service.submit("작업 이름", service.run_x, 인자…)`로 예약한다. 작업 이름은 화면에 그대로 표시되는 한글 문자열이다. 없는 대상은 `LookupError` → `HTTPException(404)`로, 업무 거절은 `ValueError`로 던진다.
7. **서버가 오래 걸려도 HTTP 요청이 막히는 작업이면 `exclusive`를 쓴다.** `with self.exclusive("라벨"):`은 진행 중인 작업이 있으면 `ValueError`를 던지고, 블록 동안 새 작업 접수를 막는다(`create_statement`, `PUT /api/settings`). 블록 안에서 `Store` 잠금을 오래 쥐면 `/api/state`가 늦어질 수 있다.
8. **프런트엔드와 계약을 맞춘다.** 응답 모양은 `frontend/src/types.ts`, 폴링은 `frontend/src/hooks/useAppState.ts`(작업 중 1초, 평상시 8초)가 쓴다. `GET /api/state`에 추가한 필드는 모든 화면 폴링에 실린다는 점을 고려한다.
9. **시험을 추가한다.** `tests/`에서 `Store(tmp_path / "db")`, `service.site = Fake…`, `service.context = …`, `service.browser = lambda: None`으로 외부 접속을 대체하고(3.3절), HTTP는 `TestClient(app, base_url="http://127.0.0.1:12345")`로 `POST /api/auth/login` 후 호출한다(`tests/test_app.py:283-286`).
10. **문서를 갱신한다.** 코드 내부 기능명세, [기술설계서 14절 API 표](../프로그램_기술설계서.md), 이 문서의 1.10절 경로 표, 데이터가 늘면 [04_데이터설계서](04_데이터설계서.md).

### 6.2 지켜야 할 구조 제약

| 제약 | 이유 | 위치 |
|---|---|---|
| 작업은 한 번에 하나만 실행된다 | `max_workers=1`, 실행 중 작업이 있으면 `submit`이 거절 | `jobs.py:38,83` |
| 사이트(Playwright)는 작업 스레드에서만 쓴다 | sync API가 스레드에 묶임 | `site.py:67` |
| HTTP 핸들러에서 오래 걸리는 일을 하지 않는다 | FastAPI 스레드 풀과 DB 잠금을 점유 | 예외는 `exclusive` 구간(거래명세서·저장 위치) |
| `Store`는 잠금을 메서드 안에서만 쥔다 | 호출자가 `store.db`를 직접 쓰려면 `store.lock`을 직접 잡아야 함(`JobRunner`가 이 방식) | `jobs.py:43-44,59` |
| 잠금 순서는 `runner.lock` → `store.lock` | 반대 순서를 만들면 교착 위험 | `jobs.py:70-72` |
| 문서 파일 경로는 `store.path`로 해석한다 | 저장 위치 이동 후에도 이력 속 옛 경로가 유효하게 | `store.py:275-280` |
| 비교 판정 변경은 `compare.py` 한 곳 | 로컬 대조·지출결의서가 `compare`를 재사용 | `local_audit.py:261`, `expense.py:29` |
| 믹스인에서 새 `self.*` 속성을 쓰면 `Core.__init__`에서 만든다 | 믹스인은 자체 초기화가 없음 | `core.py:14-19` |
