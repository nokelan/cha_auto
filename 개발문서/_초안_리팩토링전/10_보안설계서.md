# 보안 설계서

- 작성일: 2026-10-26
- 대상: 새봄 문서비교 앱(로컬 FastAPI 서버 + Chromium 앱 창)의 보호 자산, 위협 모델, 방어 계층, 잔여 위험과 권고
- 문서 기준: 소스코드 직접 확인(`saebom/api.py`, `config.py`, `launcher.py`, `site.py`, `store.py`, `statement.py`, `local_audit.py`, `files.py`, `routes/*.py`, `services/core.py`, `frontend/src`)과 `.venv`(Python 3.12.1, FastAPI 0.115.0, Starlette 0.38.6)에서 임시 데이터 폴더로 수행한 읽기 전용 실험. 확인하지 못한 것은 "(추정)"으로 표시
- 관련 문서: [기술설계서 15절](../프로그램_기술설계서.md)(접근 보호 요약), [03_API명세서](03_API명세서.md)(상태코드·쿠키 규격)

기술설계서 15절은 접근 보호의 현재 구성을 요약합니다. 이 문서는 그 구성을 반복하지 않고, 15절에 없는 **위협 모델, 방어 계층별 근거 코드, 실험으로 확인한 동작, 잔여 위험과 권고**를 다룹니다. 이 앱은 AI·OCR을 쓰지 않으며, 보안 경계는 "같은 PC의 다른 웹사이트와 다른 사용자로부터 로컬 서버를 지키는 것"까지입니다. 같은 Windows 사용자 권한으로 파일을 읽는 프로그램은 경계 밖입니다(기술설계서 15절 마지막 문단과 같은 판단).

## 1. 보호 자산

저장 위치의 기본 루트는 `%LOCALAPPDATA%\SaebomCompare`이며 환경변수 `SAEBOM_DATA_DIR`로 바꿀 수 있습니다(`saebom/store.py:50`). 아래 `{root}`는 이 폴더입니다.

|---|---|---|---|
| 원본 PDF(세금계산서·계약서) | PDF 보관 폴더. 기본 `{root}\원본PDF`(`store.py:292`), 설정에서 변경 가능. 하위 `세금계산서/`, `계약서/`. 옛 버전 경로 `{root}\documents\{해시}.pdf`도 해석함(`store.py:280`) | 사업자번호, 금액, 거래처 | API로는 문서 ID로만 제공. 파일 자체는 암호화하지 않음 |

## 2. 신뢰 경계와 행위자

| 경계 | 설명 |
|---|---|
| 앱 창(Chromium 앱 모드) ↔ 로컬 서버 | 같은 PC의 루프백(`127.0.0.1`) HTTP. 서버는 `127.0.0.1`에만 바인딩(`launcher.py:79`, `launcher.py:94`) |
| 로컬 서버 ↔ 같은 PC의 다른 프로그램 | 루프백 포트는 같은 PC의 모든 프로세스·사용자가 접속할 수 있으므로 토큰과 비밀번호로 막음 |
| 로컬 서버 ↔ 사용자의 일반 브라우저 안 웹페이지 | 악성 웹페이지가 `http://127.0.0.1:{포트}`로 요청을 보낼 수 있으므로 Host·Origin·쿠키로 막음 |
| 로컬 서버 ↔ 그룹웨어(`sbgw.vercel.app`) | 전용 브라우저 컨텍스트가 로그인 쿠키로 접속. 이 사이트만 신뢰하며 PDF 다운로드 URL을 도메인으로 제한 |
| 앱 ↔ 파일 시스템 | 사용자가 고른 폴더를 읽고, PDF 보관 폴더에 쓴다. 폴더 선택은 사용자가 하며 앱은 임의 경로를 요청받아 내보내지 않음 |

행위자 가정:

| 행위자 | 가정 |
|---|---|
| A. 사용자 본인 | 신뢰. 잘못된 입력(상대경로, 큰 값)은 검증으로 막음 |
| B. 같은 PC·같은 Windows 계정의 다른 프로세스 | 파일을 직접 읽을 수 있음 → 경계 밖. 단 API를 통한 접근은 토큰·비밀번호로 막으려 함 |
| C. 같은 PC의 다른 Windows 사용자 | 루프백 포트에는 접속 가능, 사용자 프로필 폴더는 기본 ACL상 접근 불가(추정: 코드가 ACL을 설정하지 않으며 Windows 사용자 프로필의 기본 권한에 의존) |
| D. 인터넷의 악성 웹페이지(사용자의 일반 브라우저에서 열림) | 포트 번호를 알아내(추정: 포트 스캔) 요청을 보내려 하거나 DNS 리바인딩을 시도 |
| E. 그룹웨어 사이트 또는 사이트 데이터의 변조 | 첨부 URL·파일명·PDF 내용이 악의적일 수 있다고 가정(파일명·URL·PDF 검증) |

## 3. 위협 모델

| ID | 위협 | 공격 경로 | 방어(5절 참조) | 잔여 위험 |

| T8 | 외부 URL 접근(서버 측 요청 위조에 해당) | 조작된 첨부 링크로 앱이 임의 주소를 호출 | HTTPS·`sbgw.vercel.app`·`.pdf`만 허용, 리다이렉트 금지, 요청 본문의 URL은 해당 메일의 실제 첨부와 일치해야 함 | 같은 도메인의 다른 `.pdf` 경로는 허용 |

## 4. 인증 흐름

```
앱 창 시작: --app=http://127.0.0.1:{포트}/?token={실행 토큰}
  → 서버: Host·Origin 통과, query token == 실행 토큰
  → 303 "/" + Set-Cookie saebom_session={실행 토큰}; HttpOnly; Path=/; SameSite=strict
  → 화면: GET /api/auth/status → {"authenticated": false}
  → 사용자 입력 → POST /api/auth/login
  → 서버: 잠금·비교 통과 → Set-Cookie saebom_unlocked={잠금 해제 토큰}; HttpOnly; Path=/; SameSite=strict
  → 이후 /api/* 호출은 두 쿠키 모두 필요
```

| 토큰 | 생성 | 저장 | 수명 | 전달 |
|---|---|---|---|---|
| 실행 토큰(`saebom_session`) | `secrets.token_urlsafe(32)`(`launcher.py:77`) | 메모리, `instance.json`, Chromium 명령줄 | 프로세스 실행 중. 만료 시각·갱신 없음 | 첫 진입 URL 쿼리 → 쿠키 |
| 잠금 해제 토큰(`saebom_unlocked`) | `secrets.token_urlsafe(32)`(`api.py:85`) | 메모리만 | 프로세스 실행 중. 유휴 시간 만료 없음 | 로그인 성공 응답의 쿠키 |

- 두 쿠키 모두 `Max-Age`·`Expires`가 없는 세션 쿠키이고 `Secure`는 없습니다(루프백 HTTP이므로 의미가 제한됨). 서버를 다시 시작하면 두 토큰이 모두 바뀌어 이전 쿠키는 쓸 수 없습니다.
- 앱 창 프로필(`app-profile`)에 쿠키가 디스크에 남는지는 Chromium 동작에 달려 있고 확인하지 않았습니다(추정). 남더라도 다음 실행의 토큰과 달라 무효입니다.
- `GET /api/auth/status`·`POST /api/auth/login`·`POST /api/activate`만 잠금 해제 전에 호출할 수 있습니다(`api.py:131`).
- 2차 실행(중복 실행)은 `instance.json`의 포트·토큰으로 `/health` 확인 후 `Cookie: saebom_session=…`을 붙여 `/api/activate`만 호출합니다(`launcher.py:53-64`). 이 호출은 잠금을 해제하지 않습니다.

### 5.1 요약 표

| # | 계층 | 동작 | 위치 |
|---|---|---|---|
| 1 | 루프백 바인딩 | `127.0.0.1`의 임의 포트에만 소켓 바인딩 | `launcher.py:79`, `launcher.py:94` |

### 5.2 보안 헤더 적용 범위(실험으로 확인)

`create_app.protect` 미들웨어는 요청이 라우트까지 가서 응답이 만들어진 뒤에만 헤더를 붙입니다(`api.py:135-141`). 임시 앱을 `TestClient`로 호출해 확인한 결과는 다음과 같습니다.

| 응답 | CSP | nosniff | Referrer-Policy | Cache-Control |
|---|---|---|---|---|
| 정상 `/api/*`(예: `/api/auth/status`, 로그인 401·422·429) | 있음 | 있음 | 있음 | `no-store` |
| 정적 파일(`/`) | 있음 | 있음 | 있음 | 없음 |
| 미들웨어가 직접 만든 403·401, `/health` | 없음 | 없음 | 없음 | 없음 |
| 토큰 진입 303 | 없음 | 없음 | 있음 | 없음 |
| 처리되지 않은 예외로 만들어진 500 | 없음 | 없음 | 없음 | 없음 |

CSP 정책 전문은 `api.py:138`: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; worker-src 'self' blob:; connect-src 'self'; frame-ancestors 'none'; object-src 'none'; base-uri 'self'`. `form-action`은 지정하지 않았습니다. 헤더가 빠지는 응답은 모두 JSON 오류 본문이나 리다이렉트라서 즉시 위험하지는 않지만, 일관성 면에서 6절 W9로 기록합니다.

### 5.3 경로 정규화 시도에 대한 동작(실험)

`TestClient`(httpx가 일부 경로를 정규화할 수 있음)로 세션 쿠키만 가진 상태에서 `/api/state`를 여러 형태로 요청했습니다.

| 요청 경로 | 결과 |
|---|---|
| `/api/state`, `/api/state/`, `/%61pi/state`, `/api/../api/state`, `/./api/state`, `/api%2fstate` | 모두 401(잠금 해제 요구) |
| `//api/state`, `/API/state` | 404(정적 마운트가 처리, 파일 없음). API 핸들러에 도달하지 않음 |
| `/..%2fsecret.txt`, `/%2e%2e/secret.txt`(정적 폴더 밖 파일) | 404 |
| CORS 사전 요청(`OPTIONS`, `Origin: http://evil.com`) | 403 |

우회 경로는 발견하지 못했습니다. 다만 이 보호는 `path.startswith("/api/")` 문자열 검사에 의존하므로(`api.py:132`) 라우트를 `/api/` 밖에 추가하면 잠금 해제 검사를 받지 않습니다(권고 R9).

### 5.4 로그인 비교와 비ASCII 입력(실험)

비밀번호 비교는 UTF-8 바이트로 합니다(`api.py:178`). 반면 토큰·쿠키 비교는 `str`로 합니다(`api.py:124`, `129`, `133`, `163`). `secrets.compare_digest`는 `str` 인자에 비ASCII 문자가 있으면 예외를 던집니다.

```
D:\ChaAI\07_auto\.venv\Scripts\python.exe -I -c "import secrets; …compare_digest(a, b)…"
'\xe9' 'abc'  → TypeError: comparing strings with non-ASCII characters is not supported
'\xe9' '\xe9' → TypeError: comparing strings with non-ASCII characters is not supported   (같은 값끼리도 예외)
'abc' 'abd'   → False
b'\xed\x95\x9c\xea\xb8\x80' vs b'0000' → False   (bytes는 비ASCII도 정상 비교)
```

앱에 적용한 결과(임시 앱, 실행 토큰을 `TOKEN123`으로 지정):

| 요청 | 결과 |
|---|---|
| `GET /?token=<한글>`(퍼센트 인코딩) | 500 `Internal Server Error`(보안 헤더 없음) |
| `Cookie: saebom_session=<한글 바이트>` + `GET /api/state` | 500 |
| 올바른 `saebom_session`과 `saebom_unlocked=<한글 바이트>` + `GET /api/state` 또는 `/api/auth/status` | 500 |
| 로그인 본문 `{"password":"한글"}` | 401(정상 처리, UTF-8 바이트 비교) |

해석: 비ASCII 입력은 **인증을 통과시키지 않고** 500으로 끝납니다(실패 방향이 안전). 영향은 오류 응답 형식·헤더 불일치와 서버 로그의 예외 기록입니다. Host·Origin 검사가 먼저 실행되므로 이 500을 일으키려면 `Host: 127.0.0.1`이어야 합니다.

### 5.5 CSRF·교차 출처 방어의 중복 구조

| 공격 | 막는 계층 |
|---|---|
| 다른 사이트에서 `fetch`로 POST | Origin이 `http://127.0.0.1:{포트}`와 달라 3번에서 403. 설령 Origin이 없어도 `SameSite=Strict` 때문에 쿠키가 실리지 않아 401 |
| `<form>`·`<img>` 등 단순 요청 | 쿠키가 실리지 않아 401. 모든 상태 변경은 POST·PUT이며 본문 모델이 JSON을 요구함(`text/plain` 본문은 422, 실험) |
| 사전 요청(`OPTIONS`) | Origin 검사에서 403(실험). 서버에 CORS 허용 설정 없음 |
| 다른 포트의 로컬 웹서비스 | Origin이 포트까지 달라 403. 같은 사이트(포트는 구분하지 않음)라 쿠키는 브라우저가 보낼 수 있으나 Origin 검사가 먼저 막음 |
| DNS 리바인딩 | Host가 `127.0.0.1`이 아니라서 2번에서 403 |

모든 GET 라우트는 읽기 전용입니다(`routes/*.py`, 부수효과 항목 확인). `GET /api/documents/{id}`·`/api/results/{id}/csv`·`/api/statements/{file}`은 파일을 내려주지만 쿠키가 있어야 합니다.

### 5.6 수식 주입 방지의 범위

| 출력 | 방어 | 대상 문자 | 확인 |
|---|---|---|---|
| CSV(`GET /api/results/{id}/csv`) | 모든 셀을 문자열로 바꾼 뒤 접두 `'` | `=`, `+`, `-`, `@`, 탭, 캐리지 리턴으로 시작 | `routes/compare.py:139-141`. 음수 `difference`(예: `-100`)도 `'-100`이 됨 |
| 거래명세서 엑셀(`statement.build`) | 거래처(A3), 작성일(A5), 품목명(B열), 규격(C열)에 `safe_cell` 적용 | `=`, `+`, `-`, `@`로 시작(탭·CR 제외) | `statement.py:124-125`, `313-314`, `319-320` |

- 엑셀은 `openpyxl`이 `=`로 시작하는 문자열만 수식(`data_type='f'`)으로 저장합니다. 실험에서 `=1+1`만 `f`였고 `+1+1`, `-1+1`, `@SUM(1)`, 탭·CR로 시작하는 문자열은 모두 문자열(`s`)이었습니다. 따라서 엑셀 파일에서는 `=` 방어가 실질 효과를 내고, `+ - @` 접두는 보수적인 추가 방어입니다.
- 엑셀 금액(D열)과 월(E열)·날짜(A열)는 숫자·날짜·앱이 만든 문자열이라 사용자 문자열이 들어가지 않습니다(`statement.py:317-322`).
- 접두 `'`가 붙은 값은 엑셀에서 따옴표가 글자로 보일 수 있습니다.

실험에서 임시 앱에 오답을 보낸 순서: 1번째(401), 2번째 비ASCII 오답(401), 이어서 3~5번째 오답(401, 5번째가 잠금을 설정), 6번째부터 429였고 정답을 보내도 429였습니다.

## 10. 기존 문서와 어긋난 점

| # | 기존 문서의 서술 | 코드·실험으로 확인한 사실 |
|---|---|---|
| 1 | 기술설계서 15절: "시작 비밀번호는 `0000`" | 기본값이 `0000`이고 `SAEBOM_PASSWORD` 환경변수(비어 있지 않을 때)가 우선함(`config.py:14`). 기술설계서 14절 표에는 "기본 0000"이라 적혀 있어 환경변수 변경 가능성이 15절에 빠져 있음 |
| 2 | 기술설계서 15절: "API 응답에 `Cache-Control: no-store`를 지정합니다" | `/api`로 시작하는 정상 응답에만 붙고, 미들웨어가 직접 만드는 401·403·`/health` 응답과 500에는 붙지 않음(실험, `api.py:122-141`) |
| 3 | 기술설계서 15절: "CSP로 스크립트·연결 출처 등을 제한하고 외부 프레임 삽입을 막습니다" | 정상 응답에는 맞으나 미들웨어가 직접 만드는 응답·500·303에는 CSP가 없음(5.2). `style-src`에 `'unsafe-inline'`이 있고 `form-action`은 지정하지 않음 |
| 4 | 기술설계서 15절: 실행 토큰이 "인증 쿠키"로 쓰인다고만 설명 | 같은 토큰이 `instance.json`에 평문으로 저장되고 앱 창 명령줄에도 `?token=`으로 들어감(`launcher.py:95`, `118`). 15절은 `instance.json`을 "실행 정보 파일"로만 언급 |
| 5 | 기술설계서 15절: "상태 조회·로그인·기존 창 활성화 API만 비밀번호 검증 전에 허용" | 맞음(`api.py:131`). 다만 정적 파일(`/`)도 잠금 해제 없이 세션 쿠키만으로 제공됨(`api.py:129-135`, 실험) — 화면 코드가 잠금 해제 전에 내려가는 것은 설계상 필요하지만 15절에는 명시되어 있지 않음 |
