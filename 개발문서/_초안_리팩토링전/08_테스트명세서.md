## 1. 테스트 체계 개요

| 구분 | 위치 | 건수 | 외부 의존 | 한 줄 설명 |
|---|---|---|---|---|
| pytest 단위·API 테스트 | `tests/test_*.py` 7개 | 74건(수집 확인) | 없음(네트워크·브라우저 미사용) | `tests/fixtures`의 PDF와 `tmp_path`의 임시 DB·폴더만 사용한다. |
| 통합 검증 스크립트 | `scripts/verify_*.py` 6개 | 스크립트별 항목 수는 6절 | 빌드된 `frontend/dist`, Playwright Chromium(또는 Chrome), 일부는 실제 그룹웨어 사이트 | `launcher.py`(또는 EXE)를 격리 데이터 폴더로 띄우고 브라우저로 화면을 조작한다. |

실행 전제는 다음과 같다.

- pytest 설정은 `pytest.ini:4`의 `testpaths = tests` 한 줄뿐이다. `tmp/` 안의 백업 사본이 함께 수집되는 것을 막기 위한 설정이다(`pytest.ini:1-3` 주석).
- `tests/conftest.py`와 `tests/__init__.py`는 없다. 공용 fixture 없이 각 파일이 헬퍼 함수를 직접 갖고, `test_local_audit.py:20`은 `from test_contracts_import import …`로 다른 테스트 파일의 헬퍼(`BASE`, `FILE_BASE`, `FakeRequest`, `FakeSite`, `static_dir`, `unlock`)를 가져온다. pytest 기본 import 모드가 `tests/`를 `sys.path`에 넣기 때문에 동작한다. `test_contracts_import.py`의 이름을 바꾸거나 삭제하면 `test_local_audit.py`가 깨진다.
- `saebom` 패키지는 설치되어 있지 않고 현재 디렉터리(`07_auto`)가 `sys.path`에 들어가야 import된다. `python -I -m pytest`(격리 모드)로 수집하면 7개 파일 모두 `ModuleNotFoundError: No module named 'saebom'`으로 수집 오류가 난다(수집으로 확인). `python -m pytest` 형태로 실행해야 한다.
- 수집은 파일·DB를 만들지 않는다. 테스트 모듈이 import하는 `saebom` 모듈에는 모듈 수준의 `Store()` 생성이 없고(`Store()`는 `launcher.py:153`에서만 호출), `Store`·`Service`·`create_app`은 각 테스트 함수 안에서만 만들어진다. `Store.__init__`이 폴더·DB를 만드는 시점은 테스트 실행 때다(`saebom/store.py:49-71`).
- 한글 출력이 깨지면 `-X utf8`을 붙인다. 파라미터 ID가 `\uc138…`로 이스케이프되어 보이는 것은 수집 출력의 표시 방식이며 동작과 무관하다.
- 경고는 `starlette/testclient.py:40`의 `anyio.abc.BlockingPortal` 폐기 예정 경고 1건이 남는다(수집 시 확인). 기술설계서 17절의 설명과 같다.

## 9. 새 테스트 추가 규칙

현재 코드에서 읽어 낸 관례이며 프로젝트 지침(`CLAUDE.md`)과 일치하게 정리한다.

1. **위치와 이름**: pytest는 `tests/test_<주제>.py`, 함수는 `test_<동작>`. `pytest.ini:4`가 `tests`만 수집한다. 통합 스크립트는 `scripts/verify_<주제>.py`이며 pytest가 수집하지 않는다.
2. **격리**: `Store`는 항상 `tmp_path` 아래 폴더를 명시해 만든다. 인자 없이 `Store()`를 만들면 `%LOCALAPPDATA%\SaebomCompare`(사용자 실데이터)를 연다(`saebom/store.py:50`). 정적 폴더도 `tmp_path`에 만든다.
3. **네트워크·브라우저 금지**: 사이트는 `service.site`를 대역으로 교체하고, 다운로드는 `service.context`와 `service.browser`를 교체한다(4.2절). 새 대역은 `FakeSite`처럼 필요한 메서드만 둔다.
4. **fixture**: 가능한 한 `tests/fixtures`의 기존 PDF를 쓴다. 새 PDF가 필요하면 출처와 변경 여부를 [tests/fixtures/README.md](../tests/fixtures/README.md)에 적는다. `.gitignore`가 `*.pdf`를 무시하고 `!tests/fixtures/*.pdf`만 예외이므로 다른 위치의 PDF는 저장소에 올라가지 않는다. PDF는 `.gitattributes`의 `*.pdf -text` 때문에 바이너리로 유지된다.
5. **시간 의존 제거**: `expense.draft`처럼 오늘 날짜를 쓰는 함수는 기준일을 인자로 고정한다. 비동기 작업을 기다릴 때는 상한이 있는 반복 대기를 쓰고 상한 초과 시 `AssertionError`를 던진다(`test_contracts_import.py:295-301` 패턴).
6. **인증이 필요한 API 테스트**: 먼저 `GET /?token=…`으로 세션 쿠키를 받고 `POST /api/auth/login`을 호출한다. 비밀번호는 `config.APP_PASSWORD`를 쓰는 `unlock()` 헬퍼를 재사용한다(리터럴 `'0000'`은 환경변수 설정 시 깨진다).
7. **주석·기능명세**: `07_auto/CLAUDE.md`·`MEMORY.md` 지침대로 모든 테스트 함수와 헬퍼에 `[기능명세]` 주석(목적·입력·출력·처리·예외·부수효과)을 단다. 기존 테스트 파일이 이 형식을 쓴다.
8. **판정 용어**: 단언에서 판정 문자열은 `일치`·`불일치`·`확인 필요`·`처리 실패`(로컬 대조는 `계약서 없음` 추가)를 코드의 값 그대로 쓴다.
9. **사이트 의존 기대값**: 실제 사이트 데이터를 기대값으로 쓰는 검증(`verify_*.py`)은 스크립트 머리 주석에 기준 날짜를 적고, 사이트 데이터가 바뀌면 갱신한다(기존 관례).
10. **수집 확인**: 추가 후 `--collect-only -q`로 건수가 늘었는지, 새 테스트가 다른 파일의 헬퍼에 의존하지 않는지(`test_local_audit.py:20` 같은 교차 import 포함) 확인하고 이 문서의 건수·표를 갱신한다.

## 11. 발견 사항(수정하지 않음)

1. **`-I` 격리 모드 수집 실패**: `python -I -m pytest`는 현재 디렉터리가 `sys.path`에 없어 7개 파일이 `ModuleNotFoundError`로 수집되지 않는다. `pytest.ini`에 `pythonpath = .`를 두면 막을 수 있다(미적용).
2. **`SAEBOM_PASSWORD` 설정 시 테스트·검증 스크립트 실패**: `config.APP_PASSWORD`는 import 시점 환경변수 값이다. 리터럴 `'0000'`을 쓰는 `test_app.py`와 `verify_*.py` 5종의 로그인이 실패하게 된다(코드 판단, 실행 확인 없음).
3. **테스트 간 교차 import**: `test_local_audit.py:20`이 `test_contracts_import`의 헬퍼를 가져온다. 공용 `conftest.py`가 없어 파일 이름 변경이 연쇄 오류를 낸다.
4. **사이트 의존 기대값의 취약성**: `verify_contracts.py`·`verify_expense.py`·`verify_local_audit.py`는 2026-10-21 사이트 데이터와 `cases.json`에 묶여 있어 사이트 데이터가 바뀌면 코드와 무관하게 실패한다. `verify_expense.py`는 실제 상신(격리 프로필 localStorage)을 만든다.
5. **`verify_ui.py`는 사용자 실데이터 전제**: 빈 PC나 새 사용자 계정에서는 실행할 수 없고, 출력 폴더가 시각 없이 `tmp/ui-review` 고정이다.
6. **동기화·종료 경로 미검증**: `Service.sync`·`fetch_mails`·`launcher.py` 시작·종료 흐름은 pytest도 verify 스크립트도 다루지 않는다(7.2절).
7. **미사용 fixture**: 별빛보안·소담클라우드 세금계산서와 계약서 `020`·`022`가 어떤 테스트에서도 쓰이지 않는다. 판정 케이스를 늘릴 후보이거나 정리 대상이다.
8. **`tests/` 바로 아래 잔여 PDF 3개**: 출처 불명(6.1절). 저장소에는 올라가지 않지만 `tests/` 폴더를 혼란스럽게 한다.
9. **빌드 후 검증 없음**: `scripts/build.py`는 pytest나 `verify_*.py`를 실행하지 않는다. 배포 검증은 `SAEBOM_VERIFY_EXE`를 쓰는 수동 절차다.
