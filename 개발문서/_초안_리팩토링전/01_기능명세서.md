## 3. 공통 규약

### 3.1 응답 규약

| 상황 | 상태 코드 | 본문 | 근거 |
|---|---|---|---|
| 업무 규칙 위반(`ValueError`) | 400 | `{"detail": 메시지}` | `saebom/api.py:151`(`bad_input`) |
| 요청 스키마 위반(Pydantic) | 422 | FastAPI 기본 형식(별도 핸들러 없음) | `saebom/api_models.py`, 재정의 핸들러 없음 |
| 대상 없음 | 404 | 라우트별 문구 | `saebom/routes/*.py` |
| 호스트·출처 불허 | 403 | "로컬 접속만 허용됩니다." / "다른 사이트의 요청은 허용되지 않습니다." | `saebom/api.py:117-120` |
| 실행 세션 쿠키 없음 | 401 | "EXE를 실행해 앱 화면을 다시 열어 주세요." | `saebom/api.py:129` |
| 비밀번호 잠금 미해제 | 401 | "비밀번호를 입력해 프로그램을 잠금 해제해 주세요." | `saebom/api.py:133` |
| 비밀번호 연속 실패 잠금 | 429 | "비밀번호를 여러 번 틀렸습니다. N초 후 다시 시도해 주세요." | `saebom/api.py:173-177`(`login`) |

프런트엔드의 `api()` 함수는 응답의 `detail`이 문자열이면 그대로 화면에 보이고, 문자열이 아니면(422) "입력값을 확인해 주세요."를 보입니다(`frontend/src/api.ts:58`의 `api` 함수).

### 3.2 작업 접수 방식

기능은 세 가지 방식 중 하나로 실행됩니다. 어떤 방식인지에 따라 "동시에 다른 작업을 할 수 있는가"가 달라집니다.

| 방식 | 해당 기능 | 특징 |
|---|---|---|
| 백그라운드 작업(job) | F-01, F-02, F-03, F-04, F-08, F-11, F-12, F-14 | `JobRunner.submit`이 `{id}`를 즉시 반환하고 작업 스레드에서 실행. 다른 작업이 진행 중이면 400 "현재 작업이 끝난 뒤 실행해 주세요."(`saebom/jobs.py:21,83`) |
| 배타 구간 안의 동기 요청 | F-10(거래명세서 생성), F-13(저장 위치 변경) | `JobRunner.exclusive`로 `busy`를 걸고 요청 스레드에서 끝까지 실행. 작업이 진행 중이면 400(`saebom/jobs.py:128`) |
| 일반 동기 요청 | 나머지(조회·초안·CSV·원문·로그인 등) | 잠금 검사 없이 즉시 응답 |

작업 스레드 한 개가 모든 백그라운드 작업을 직렬로 처리합니다. 자세한 스레드·잠금 구조는 [02_시스템구성도](02_시스템구성도.md) 4절을 봅니다.

### 3.3 공통 사전조건

- 모든 `/api/*` 요청은 실행 세션 쿠키와 잠금 해제 쿠키가 필요합니다. 예외는 `/api/auth/status`, `/api/auth/login`, `/api/activate`입니다(`saebom/api.py:131-133`). 이하 기능 표의 "사전조건"에서는 이를 "잠금 해제"로 줄여 씁니다.
- 그룹웨어에 접속하는 기능(F-01, F-02의 다운로드, F-08, F-11, F-12의 계약서 확보, F-14)은 앱 전용 브라우저(`browser-profile/`)에 그룹웨어 로그인 상태가 있어야 합니다. 로그인 여부를 코드가 직접 검사하지는 않으며, 목록이 비면 `check_lists`가 실패시킵니다(`saebom/site.py:232`).

## 4. 문서비교 기능(F-01~F-07)

### 4.1 F-01 목록 동기화

| 항목 | 내용 |
|---|---|
| 목적 | 그룹웨어의 받은 메일함과 계약 문서함 목록을 앱 DB의 스냅샷으로 가져온다. |
| 진입 화면 | 메일 · 문서 선택. 상단 "목록 새로고침" 버튼(`frontend/src/App.tsx:352-356`, `act('sync')`). 진행 중에는 버튼이 비활성화된다. |
| 사전조건 | 잠금 해제, 진행 중인 작업 없음, 전용 브라우저의 그룹웨어 로그인 |
| 입력 | 없음(본문 없는 `POST`) |
| 처리 요약 | 전용 브라우저를 열고(`Core.browser`) 메일함(`#/mail`, 제목 "받은 메일함" 최대 30초 대기)과 계약 문서함(구분 "전체")의 표 행을 읽는다(`saebom/services/compare_service.py:14-22`, `saebom/site.py:155,173`). 두 목록 중 하나라도 비어 있으면 중단하고, 아니면 `Store.snapshot`이 `items` 테이블을 비우고 새로 채운다. 수집 방식은 [수집·다운로드 동작 원리 6절](../AI없이_텍스트수집_PDF다운로드_동작원리.md)을 따른다. |
| 출력·상태 변화 | `items` 전체 교체, `meta.synced`에 시각 저장(`saebom/store.py:80`). 작업은 `total=2`, 완료 메시지 "목록 저장 완료". `documents`, `results`, `contract_imports`, `contract_status`는 바뀌지 않는다. |
| 오류·거절 | 작업 중 → 400 "현재 작업이 끝난 뒤 실행해 주세요." 목록이 비어 있음 → 작업 실패 "작업 실패: 메일·계약 목록이 비어 있습니다. 전용 브라우저의 로그인과 화면을 확인해 주세요." 계약 표가 7열이 아님 → "계약 목록 양식이 바뀌었습니다. 기존 목록을 유지합니다."(`saebom/site.py:184-185`). 메일함 제목을 30초 안에 못 찾으면 Playwright 시간 초과로 작업 실패(메시지 본문은 Playwright가 만든다, 추정). 실패해도 기존 스냅샷은 유지된다(`snapshot` 호출 전에 중단). 프로그램 종료 확인(`closing`)은 하지 않는다. |
| 관련 파일 | `saebom/routes/compare.py:23`, `saebom/services/compare_service.py:14`, `saebom/site.py`, `saebom/store.py:80` |

### 4.2 F-02 PDF 다운로드

| 항목 | 내용 |
|---|---|
| 목적 | 선택한 세금계산서 PDF와 계약서 PDF를 PC 폴더에 저장하고 텍스트를 읽어 DB에 등록한다. |
| 진입 화면 | 메일 · 문서 선택 2단. "선택 문서 다운로드" 버튼(`frontend/src/screens/compare/MailsScreen.tsx:215`). 모든 선택 행에 계약이 연결되어야(`connected`) 활성화된다(같은 파일 56줄). |
| 사전조건 | 잠금 해제, 진행 중인 작업 없음, F-01로 동기화된 목록, 전용 브라우저 로그인 |
| 입력 | `{pairs: [{mail_id, contract_id, invoice_url}, ...]}`. 1~500건(`saebom/api_models.py:17`) |
| 처리 요약 | 라우트가 `validate_pairs`로 연결을 검증한 뒤 작업 `문서 다운로드`를 접수한다(`saebom/routes/compare.py:35`). 작업은 URL 기준으로 중복을 제거한 파일을 하나씩 `download_one`으로 받는다(`saebom/services/core.py:170-189`). 이미 저장한 문서(같은 URL이고 파일이 존재)는 재사용한다. 새 파일은 URL 검사(`https`, 도메인 `sbgw.vercel.app`, `.pdf`) → 요청(30초, 리다이렉트 금지) → 응답 검사(HTTP 200, `%PDF-` 시작, 50MiB 이하) → SHA-256 → `<저장폴더>/<세금계산서|계약서>/<해시 12자리>_<안전한 파일명>`에 임시 파일(`.part`)로 쓰고 교체 → `extract`로 텍스트·항목 추출 → `documents` 저장 순서로 처리한다. 상세는 [동작 원리 7~11절](../AI없이_텍스트수집_PDF다운로드_동작원리.md). |
| 출력·상태 변화 | `documents` 행 추가·갱신(`kind` 포함), PDF 파일 생성. 작업의 `done`이 파일마다 1씩 오르고 실패 목록이 `errors`에 쌓인다. 파일 하나가 실패해도 나머지는 계속 받는다. |
| 오류·거절 | 연결 검증 실패 400(F-03의 표 참고). 일부 실패 → 마지막에 "N개 파일 저장 실패. 상세 오류를 확인하고 재시도하세요."로 작업 실패 처리(저장된 파일은 유지). 파일별 오류: "대상 사이트의 PDF 다운로드 링크만 사용할 수 있습니다.", "다운로드 HTTP {상태}: {파일명}", "PDF 형식이 아니거나 파일이 50MB를 초과합니다."(`saebom/site.py:30-50`). 프로그램 종료 요청 중이면 다음 파일 전에 "프로그램 종료 요청으로 중단했습니다. 저장한 파일은 유지됩니다."로 중단(`saebom/services/compare_service.py:134-135`). |
| 관련 파일 | `saebom/routes/compare.py:35`, `saebom/services/compare_service.py:123`, `saebom/services/core.py:170`, `saebom/site.py:44,60`, `saebom/files.py` |

### 4.3 F-03 문서비교(연결 검증 포함)

| 항목 | 내용 |
|---|---|

| 처리 요약 | 요청 스레드에서 배타 구간 `저장 위치 변경`을 잡고 `Store.set_document_root`를 호출한다(`saebom/routes/system.py:36-48`). 경로 검사·쓰기 검사 후 등록된 문서마다 원본 존재·SHA-256 확인, 새 폴더로 복사·검증, 모두 성공하면 DB를 한 트랜잭션으로 갱신하고 옛 파일을 지운다. 복사·충돌 규칙은 [기술설계서 12절](../프로그램_기술설계서.md). |
| 출력·상태 변화 | `documents.disk_path` 일괄 갱신, `meta.document_root` 갱신. 응답 `{document_root}`. 거래명세서 폴더(`거래명세서/`)는 문서로 등록되지 않아 옮겨지지 않는다(`saebom/files.py:10-12`). 이동이 끝날 때까지 요청이 응답하지 않으며, 그동안 `Store` 잠금 때문에 `/api/state`도 지연될 수 있다. |
| 오류·거절 | 진행 중인 작업 또는 종료 중 → 400 "진행 중인 작업이 끝난 뒤 저장 위치를 변경해 주세요." 경로 검사 400 "PC의 절대 폴더 경로를 선택해 주세요. 네트워크 공유 폴더는 지원하지 않습니다." 원본 없음·해시 불일치·동일 이름 다른 내용 파일은 각각 "원본 파일을 찾을 수 없어 저장 위치를 유지합니다: …", "원본 파일 내용이 달라 저장 위치를 유지합니다: …", "새 폴더에 내용이 다른 같은 이름의 파일이 있습니다: …"(`store.py:338-361`). 입출력 오류(`OSError`) → 400 "저장 위치를 바꾸지 못했습니다. 기존 설정과 원본 파일은 유지됩니다. 새 폴더의 쓰기 권한과 여유 공간을 확인해 주세요. (오류 종류)". 폴더 선택 대화상자는 요청 스레드에서 Tk 창을 연다. |

### 7.3 F-15 시작 비밀번호·잠금, 로컬 접근 보호

| 항목 | 내용 |
|---|---|
| 목적 | 앱 화면에 들어가려면 비밀번호를 요구하고, 같은 PC의 앱 화면 외 접근을 막는다. |
| 진입 화면 | 실행 직후 첫 화면(`frontend/src/AccessGate.tsx`). 잠금 해제 상태가 아니면 `App`을 마운트하지 않는다. |
| 사전조건 | 앱 진입 토큰으로 열린 브라우저 세션(실행 세션 쿠키 `saebom_session`) |
| 입력 | `POST /api/auth/login` `{password: 1~128자}`(`saebom/api_models.py:70`) |
| 처리 요약 | 비밀번호는 `config.APP_PASSWORD`와 상수 시간 비교한다. 값은 환경변수 `SAEBOM_PASSWORD`가 비어 있지 않으면 그 값, 아니면 `0000`이다(`saebom/config.py:14`). 연속 5회 실패하면 30초 동안 잠그고 실패 횟수를 0으로 되돌린다. 실패 횟수와 잠금 시각은 서버 메모리에만 있어 재시작하면 초기화된다(`saebom/api.py:173-186`). 성공하면 HttpOnly·SameSite=Strict 쿠키 `saebom_unlocked`(실행마다 새로 만든 토큰)를 발급한다. 미들웨어(`api.py:115-141`)는 요청마다 순서대로 ① 호스트가 `127.0.0.1`인지 ② `Origin`이 같은 호스트인지 ③ `/health` 응답 ④ `/?token=` 최초 접속이면 세션 쿠키를 심고 `/`로 리다이렉트 ⑤ 세션 쿠키 확인 ⑥ 공개 API 3개 외의 `/api/*`는 잠금 해제 쿠키 확인 ⑦ 응답에 보안 헤더(CSP, `nosniff`, `no-referrer`, API는 `no-store`)를 붙인다. |
| 출력·상태 변화 | 성공 시 `{authenticated: true}`와 쿠키. 같은 실행의 새로고침에서는 잠금 해제가 유지되고, 프로그램을 다시 실행하면 토큰이 바뀌어 다시 묻는다. |
| 오류·거절 | 틀린 비밀번호 401 "비밀번호가 올바르지 않습니다."(잠금을 거는 5번째 실패도 401). 잠금 중에는 정답이어도 429 "비밀번호를 여러 번 틀렸습니다. N초 후 다시 시도해 주세요." 빈 비밀번호는 422(화면은 빈 입력이면 전송 자체를 막는다, `AccessGate.tsx` 의 `login`). 비밀번호 변경 화면은 없다. |
| 관련 파일 | `saebom/api.py:82-141,161-187`, `saebom/config.py:14,25-26`, `frontend/src/AccessGate.tsx` |

### 7.4 F-16 프로그램 종료·중복 실행

| 항목 | 내용 |
|---|---|
| 목적 | 앱 하나만 실행되게 하고, 종료 시 서버·브라우저·실행 정보를 정리한다. |
| 진입 화면 | 사이드바 "프로그램 종료"(작업 중에는 비활성, `App.tsx:335`), 앱 창 닫기, EXE 재실행 |

| 입력 | 종료 `POST /api/shutdown`(없음), 활성화 `POST /api/activate`(없음, 실행 세션 쿠키만 필요) |

| 오류·거절 | 앱 창을 열지 못하면 서버를 종료하고 "앱 창을 열지 못했습니다. …" 오류를 던진다. 시작 실패는 `app.log` 기록과 Windows 메시지 상자로 알린다(`launcher.py:180-188`). 환경변수 `SAEBOM_NO_OPEN=1`이면 앱 창을 열지 않는다(검증 스크립트용, `launcher.py:109`). 작업 중 창을 닫으면 작업 스레드가 끝날 때까지 서버 정리가 기다린다(작업이 `closing`을 확인하는지에 따라 다름, [02_시스템구성도](02_시스템구성도.md) 4.5절). |
| 관련 파일 | `launcher.py`, `saebom/routes/system.py:95,109`, `saebom/api.py:98` |

### 7.5 F-17 작업(job) 진행·이력

| 항목 | 내용 |
|---|---|
| 목적 | 오래 걸리는 작업의 진행 상황·실패 파일·결과 ID를 화면에 보이고, 재시작 뒤에도 마지막 상태를 남긴다. |
| 진입 화면 | 모든 화면 위쪽의 작업 표시줄(가장 최근 작업 1건, `App.tsx:366-386`) |
| 사전조건 | 잠금 해제 |
| 입력 | 없음. `GET /api/state`의 `jobs`를 읽는다. |
| 처리 요약 | `JobRunner.submit`이 실행 중 작업·`closing`·`busy`가 없을 때만 작업을 접수하고 `{id, kind, status:"running", message:"작업 준비 중", done:0, total:1, errors:[], created}`를 만들어 `meta.jobs`에 저장한다. 최근 20개만 보관한다(기존 19개 + 새 작업, `saebom/jobs.py:86-88`). 작업 함수가 문자열을 반환하면 그것이 완료 메시지이고 아니면 "작업 완료"다(`jobs.py:101`). 예외는 "작업 실패: …"로 저장한다. 프로그램을 다시 시작하면 `running`으로 남은 작업은 `failed`와 "이전 실행이 종료되었습니다. 저장 파일은 유지되며 작업을 다시 실행할 수 있습니다."로 바뀐다(`jobs.py:43-49`). |
| 출력·상태 변화 | 작업 종류 문자열: `목록 동기화`, `문서 다운로드`, `오프라인 비교`, `보정 후 재비교`, `전용 브라우저`, `계약서 가져오기`, `지출결의서 상신`, `로컬 세금계산서 대조`. 화면은 완료된 새 작업의 `result_id`가 있으면 해당 결과를 연다. 진행률은 `done/total`이고 `errors`가 있으면 "실패 파일 N건 보기"로 펼친다. |
| 오류·거절 | 접수 거절은 400 "현재 작업이 끝난 뒤 실행해 주세요." 작업 실패는 접수가 아니라 작업 상태(`failed`)로 나타난다. 작업 진행 중에 `done`이 `total`을 넘지 않는다는 보장은 코드에 없다(작업마다 `total`을 직접 갱신함). |
| 관련 파일 | `saebom/jobs.py`, `saebom/services/core.py:79-113`, `frontend/src/App.tsx`, `frontend/src/hooks/useAppState.ts` |
