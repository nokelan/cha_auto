### 1.1 가상환경과 의존성 설치

명령은 `사용방법.md`의 "개발 환경" 단락(한 줄)을 순서로 풀어 쓴 것이다. 이 문서에서는 실행하지 않았다.

```powershell
cd D:\ChaAI\07_auto
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
npm.cmd ci --prefix frontend
```

- `requirements.txt`는 직접 의존 8개를 정확한 버전으로 고정한다(9절). 같은 환경을 그대로 재현하려면 `requirements-lock.txt`(전이 의존 포함 40줄)를 쓴다: `pip install -r requirements-lock.txt`. 이 파일은 UTF-8 BOM과 CRLF 줄바꿈이다(`file` 명령으로 확인). pip는 BOM을 읽을 수 있어 설치에는 문제가 없을 것으로 본다(추정).
- Playwright 1.60.0이 요구하는 Chromium은 `chromium-1223`이다. `SaebomCompare.spec:4`가 `C:\Users\KOSA\AppData\Local\ms-playwright\chromium-1223`을 복사 대상으로 적고 있어 설치 위치가 `%LOCALAPPDATA%\ms-playwright`임을 보여 준다. `playwright` 버전을 올리면 Chromium 빌드 번호도 바뀐다.
- 한글 출력: 콘솔에서 한글이 깨지면 `python -X utf8 …`로 실행한다. 앱 코드는 로그와 JSON을 UTF-8로 쓴다(`launcher.py:154`의 `encoding="utf-8"`). 검증 스크립트 `verify_statement.py`는 표준 출력을 `errors='replace'`로 바꾼다(`scripts/verify_statement.py:426`).
- Python 패키지와 PyInstaller는 모두 `.venv`에 설치한다. `scripts/build.py`는 `sys.executable`로 PyInstaller를 호출하므로 반드시 `.venv`의 Python으로 실행해야 한다(`scripts/build.py:36`).

### 4.3 빌드의 이식성·주의점

1. **`build.py`는 spec 파일을 쓰지 않는다.** 인자(`--add-data` 등)를 직접 넘기고, PyInstaller가 그 결과로 `SaebomCompare.spec`을 `07_auto`에 새로 쓴다. 그래서 spec 안의 `D:\ChaAI\07_auto\…`와 `C:\Users\KOSA\AppData\Local\ms-playwright\chromium-1223` 절대 경로(`SaebomCompare.spec:4`)는 빌드한 PC의 경로가 기록된 부산물이며, 다른 PC에서는 `build.py`를 다시 실행하면 새로 만들어진다. 이 spec을 직접 `pyinstaller SaebomCompare.spec`로 쓰면 다른 PC에서는 경로가 맞지 않는다. `.gitignore`가 `*.spec`을 제외한다.
2. `npm.cmd`는 Windows 전용이다(`:26-27`).
3. `licenses/` 복사가 현재 가상환경의 모든 설치 패키지를 훑는다(`:47-54`). 개발·빌드 도구(`pytest`, `pyinstaller` 등)의 라이선스도 같이 들어간다. 반대로 `THIRD_PARTY_NOTICES.md`는 수작업 목록이다(PyInstaller 항목은 있고, `pytest` 등 개발 도구는 없음).
4. 빌드 후 자동 검증이 없다. `build.py`는 테스트나 `verify_*.py`를 실행하지 않는다(`SAEBOM_VERIFY_EXE`로 수동 검증, 08 문서 8절).
5. 코드 서명이 없다(`SaebomCompare.spec`의 `codesign_identity=None`). 처음 실행하는 PC에서 Windows SmartScreen 경고가 뜰 수 있다(추정). 설치형(MSI)·자동 업데이트도 없다(기술설계서 16.1절).
6. spec의 `upx=True`는 PyInstaller 기본값이며 UPX가 설치되어 있을 때만 압축한다(추정, 설치 여부는 확인하지 않음).
7. 빌드 중간 산출물(`frontend/dist`, `frontend/node_modules`, `build/`, `dist/`)은 모두 `.gitignore` 대상이다.

| 시작 실패 | `실행하지 못했습니다` 대화상자가 `%LOCALAPPDATA%\SaebomCompare\app.log`를 확인하라고 안내한다(`launcher.py:186`) |
| 업데이트 | 앱을 종료한 뒤 새 ZIP의 폴더로 기존 `SaebomCompare` 폴더를 교체한다. 데이터는 `%LOCALAPPDATA%\SaebomCompare`에 따로 있어 그대로 유지된다. 새 버전이 필요로 하는 테이블·열은 시작 시 자동 보강된다(`CREATE TABLE IF NOT EXISTS`, 없는 열은 `ALTER TABLE ADD COLUMN`, `saebom/store.py:58-71`). 반대로 낮은 버전으로 되돌리는 경우는 지원하지 않는다(추정: 새 테이블은 무시되고 새 열은 남을 뿐이라 동작할 수 있으나 검증하지 않음) |
| 다중 계정 | 데이터가 사용자별 `%LOCALAPPDATA%`에 있어 Windows 계정마다 별도 데이터다 |

## 6. 운영

### 6.1 데이터 파일

데이터 루트는 기본 `%LOCALAPPDATA%\SaebomCompare`(`SAEBOM_DATA_DIR`로 변경 가능). 구조는 기술설계서 11.2절과 같으며, 코드로 확인한 각 항목의 생성 시점은 다음과 같다.

| 경로 | 생성 시점·내용 | 백업 대상 |
|---|---|---|
| `saebom.sqlite3`(+ `-wal`, `-shm`) | 시작 시 `Store`가 생성. WAL 모드(`saebom/store.py:54-55`). 테이블: `items`, `documents`, `results`, `meta`, `contract_imports`, `contract_status`(`:59-64`) | **필수.** 목록·추출값·비교 이력·설정(`meta`)·가져온 계약·품의완료 상태 |
| `documents/` | 시작 시 빈 폴더 생성(`store.py:52`). `disk_path`가 없는 옛 문서의 `<해시>.pdf` 호환용(`store.py:280`) | 옛 데이터가 있으면 포함 |
| `원본PDF/` | 저장 위치를 지정하지 않았을 때의 기본 PDF 폴더(`store.py:292`). 폴더는 PDF 저장 시 만들어진다 | PDF 폴더 설정에 따름(아래) |
| 사용자가 지정한 PDF 폴더 | `세금계산서/`, `계약서/`(해시 앞 12자+`_`+원본명), `거래명세서/`(앱이 만든 엑셀. DB에 등록되지 않음) | **필수.** 세 폴더 모두 |
| `app-profile/` | 앱 창 Chromium 프로필(`launcher.py:117`) | 불필요(재생성) |
| `browser-profile/` | 그룹웨어 자동화 Chromium 프로필(`saebom/services/core.py:17`). 사이트 로그인·지출결의서 상신 기록(localStorage)이 여기 있다 | 선택. 지출결의서 상신 기록을 유지하려면 포함. 프로필 쿠키는 Windows 계정에 묶여 있어 다른 PC로 옮겨도 로그인이 풀릴 수 있다(추정) |
| `app.log` | 6.4절 | 선택 |
| `instance.json` | 실행 중 포트·세션 토큰(`launcher.py:95`). 종료 시 삭제(`:172`) | 불필요. 토큰이 들어 있으므로 복사·공유하지 않는다 |

`saebom.sqlite3`의 `meta` 테이블에는 `document_root`(PDF 폴더 경로, 문자열), `jobs`(최근 작업 최대 20개, JSON), `synced`, `local_invoice_folder`, `local_audit`가 저장된다(`saebom/jobs.py:60`, `store.py:289-292`, 08 문서 2.4절의 `meta` 테스트). `documents.disk_path`에는 PDF의 **절대 경로**가 저장된다(`store.py:280`).

### 6.2 백업

1. 앱을 종료한다(WAL 파일이 정리되고 복사 도중 변경이 없다).
2. `saebom.sqlite3`와 같은 폴더의 `saebom.sqlite3-wal`, `saebom.sqlite3-shm`이 남아 있으면 함께 복사한다. 정상 종료하면 WAL이 DB에 반영된다(추정: SQLite 기본 동작).
3. PDF 폴더 전체(`세금계산서/`, `계약서/`, `거래명세서/`)를 복사한다.
4. 상신 기록까지 보존하려면 `browser-profile/`도 복사한다.

앱에는 백업·복원 기능이 없다. 기술설계서 18절 9번도 자동 백업이 범위 밖임을 밝힌다.

### 6.5 중복 실행과 종료

- **중복 실행**: 데이터 루트 경로의 SHA-256 앞 16자로 `Local\SaebomCompare-…` Mutex를 만든다(`launcher.py:42`). 이미 있으면 두 번째 프로세스는 `instance.json`의 포트로 `/health`를 확인하고(최대 40회, 0.25초 간격) 세션 쿠키로 `/api/activate`를 POST해 기존 창을 앞으로 가져온 뒤 조용히 끝난다(`launcher.py:53-66`). 40회 안에 연결하지 못해도 오류 표시 없이 끝난다.
- **정상 종료**: 앱 창을 닫거나 화면의 프로그램 종료(`POST /api/shutdown`)를 누르면 `server.should_exit`가 켜진다(`launcher.py:90-91`, `saebom/routes/system.py:95-99`). 이후 `main`의 정리 순서는 창 종료 최대 10초 대기 → `instance.json` 삭제 → 소켓 닫기 → Mutex 닫기다(`launcher.py:169-175`). 서비스 종료는 작업 실행기가 진행 중 작업이 끝나길 기다린 뒤(`ThreadPoolExecutor.shutdown(wait=True)`, `saebom/jobs.py:148-152`) 사이트 브라우저를 닫는다. 작업 루프는 종료 요청을 보고 `프로그램 종료 요청으로 중단했습니다.`라는 오류로 멈춘다(`compare_service.py:135`, `contracts_service.py:30`, `local_audit_service.py:117`).
- **강제 종료**: 작업 관리자로 끝내면 Mutex는 OS가 정리하지만 `instance.json`이 남는다. 다음 실행이 새 값으로 덮어쓰므로 문제가 없다(추정). `running`으로 남은 작업은 다음 실행 때 `failed`(`이전 실행이 종료되었습니다. …`)로 바뀐다(`saebom/jobs.py:47-49`, 테스트 있음). 저장 위치 이동 중 강제 종료는 복사본 중복이 남을 수 있고 복구 저널은 없다(기술설계서 18절 7번).

## 11. 발견 사항(수정하지 않음)

1. **빌드 이식성**: `build.py`가 `npm.cmd`를 하드코딩하고 번들 대상 Chromium을 현재 PC의 `executable_path`에서 구한다. 다른 OS·다른 PC에서는 사전 설치가 맞아야 한다. spec의 절대 경로는 재사용 불가다.
2. **`licenses/` 수집 범위**: 가상환경의 모든 패키지(개발 도구 포함)를 훑는다. 번들 대상 패키지만 골라 복사하는 로직이 없다.
3. **`app.log` 무제한 증가**: 회전·삭제 정책이 없다. 장기 운영 시 수동 정리가 필요하다.
4. **다른 PC 이관 제약**: `documents.disk_path`가 절대 경로이고 저장 위치 이동 기능이 원본 존재를 전제로 하므로, 경로가 달라지는 이관에 대한 지원이 없다(6.3절).
5. **`SAEBOM_PASSWORD`와 `0000` 문서화**: 비밀번호 변경 방법(환경변수)이 사용자 문서에 없고 기본 비밀번호가 `사용방법.md`에 그대로 적혀 있다. 환경변수는 EXE 실행 전에 설정해야 하며 영구 설정 방법에 대한 안내가 없다.
6. **프런트 dev 서버·린트·테스트 부재**: 화면 수정 시마다 전체 빌드가 필요하다(3절).
7. **의존성 목록 혼재**: `requirements.txt`가 런타임과 개발·빌드 도구를 구분하지 않고, `httpx`가 테스트 전용인지 앱 코드 의존인지 코드만으로는 구분되지 않는다(앱 코드는 import하지 않음, 추정). `THIRD_PARTY_NOTICES.md`에는 `pytest`·`httpx`가 없다.
8. **`documents/`(07_auto 직하)와 `tests/` 잔여 PDF**: 과거 실행으로 만들어진 것으로 보이는 폴더·파일이 작업 트리에 남아 있다. 모두 `.gitignore` 대상이다.
