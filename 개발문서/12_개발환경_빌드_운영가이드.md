## 1. 환경 구성

Windows에서 Python 3.12·Node.js·npm·Tcl/Tk·Playwright Chromium을 준비한다. Node 지원 버전의 정본은 frontend/package-lock.json의 pdfjs-dist·Vite engines다. 앱 화면과 사이트 자동화는 별도 Chromium 프로필을 사용한다. 일부 검증은 Google Chrome도 필요하다.

```powershell
Set-Location D:\ChaAI\07_auto
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m playwright install chromium
npm.cmd ci --prefix frontend
npm.cmd run build --prefix frontend
.\.venv\Scripts\python.exe -X utf8 scripts/copy_pdf_assets.py
.\.venv\Scripts\python.exe -X utf8 launcher.py
```

requirements.txt는 실행 직접 의존성 5개(fastapi·uvicorn·pdfplumber·openpyxl·playwright), requirements-dev.txt는 런타임 포함+pyinstaller·httpx·pytest다. 기존 requirements-lock.txt는 전이 의존성까지 고정한 자료로 보존했다. `.env` 자동 로더는 없으므로 프로세스 환경에 설정한다. package.json의 명령은 build 하나이며 dev 서버·핫 리로드는 제공하지 않는다.

## 2. 환경변수

| 이름 | 미설정·빈 값 처리 | 사용처·의미 |
|---|---|---|
| SAEBOM_PASSWORD | 기본 앱 비밀번호 유지. 값은 문서·로그에 기록하지 않음 | `saebom/config.py:14`, import 때 결정. 실행 전 지정 |
| SAEBOM_OWN_BIZ | 내장 자사 번호 유지 | `saebom/config.py:20`, 계약 상대 사업자 추출·수입 적격 확인 |
| SAEBOM_EXPENSE_PREFIX | 내장 팀명 접두어 유지 | `saebom/config.py:23`, 지출결의서 제목 |
| SAEBOM_DATA_DIR | LOCALAPPDATA/SaebomCompare | `saebom/store.py:52`, DB·프로필·로그·실행정보의 루트 |
| SAEBOM_NO_OPEN | 정확히 1일 때만 앱 창 생략 | `launcher.py:109`, 검증 서버용. 사이트 자동화 브라우저는 별개 |
| SAEBOM_VERIFY_EXE | 미설정이면 소스 launcher 사용 | `scripts/verify_statement.py:136`, verify_contracts 도우미도 사용. 지정한 배포본 검사 |
| LOCALAPPDATA | 없으면 사용자 홈 | `saebom/store.py:52`, 기본 데이터 위치의 상위 |
| PLAYWRIGHT_BROWSERS_PATH | Playwright 기본 탐색 | 번들이 있으면 launcher/site가 browser 경로를 지정 |

사이트 주소·허용 호스트·50MiB PDF·100페이지·500연결·로그인5회/30초는 config 상수다. 사이트 주소 환경변수는 도입하지 않았다. 자사번호·접두어도 빈 문자열이면 기본값으로 대체한다. 환경변수 변경은 실행 중 프로세스에 반영되지 않으므로 재시작한다.

## 3. 개발 실행과 데이터 격리

launcher가 127.0.0.1 임의 포트를 열고, 실행별 토큰을 instance.json에 기록한다(`launcher.py:76`). 토큰은 화면·로그·문서에 복사하지 않는다. Windows Mutex 이름은 데이터 경로 해시로 만들어 같은 데이터 폴더의 중복 실행을 막는다(`launcher.py:37`). 테스트는 별도 SAEBOM_DATA_DIR을 사용한다.

Vite 빌드가 frontend/dist를 비우므로 PDF.js의 cmaps·standard_fonts·wasm 복사는 반드시 빌드 뒤에 한다(`scripts/copy_pdf_assets.py:13`). 이 순서를 빠뜨리면 글꼴·PDF 표시 문제가 날 수 있다.

## 4. EXE 생성과 배포

실행 중인 배포 앱이 종료된 뒤에만 다음 명령을 실행한다. 2026-10-26 후속 요청에서 종료 상태 확인 후 실제 재빌드·검증·정상 재실행을 완료했다(14번8절).

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/build.py
```

| 순서 | 동작·실패 |
|---|---|
| 1 | find_npm이 PATH에서 npm.cmd/npm을 찾음. 없으면 설치 안내 RuntimeError |
| 2 | npm ci→tsc/Vite 빌드→PDF.js 자산 복사. 하위 명령 실패 시 즉시 중단 |
| 3 | 설치 Chromium 경로 존재 확인 |
| 4 | PyInstaller --onedir --windowed, 정적 화면·거래명세서 템플릿·Chromium·Tk 포함 |
| 5 | 사용방법·외부 구성요소 고지 및 설치 패키지 라이선스 복사 |
| 6 | dist/SaebomCompare-Windows.zip 생성, READY/ZIP 경로 출력 |

근거: `scripts/build.py:21`·`scripts/build.py:37`. spec은 스크립트 실행 결과로 다시 만들어진다. 과거 PC의 절대경로가 든 spec을 재사용하지 않는다. npm 탐색의 이식성을 개선했으나 배포 대상은 Windows다. EXE만 단독 배포하지 않고 dist/SaebomCompare 전체를 전달한다. 빌드 명령 자체는 테스트를 수행하지 않는다.

배포 검증은 별도 테스트 데이터에서 SAEBOM_VERIFY_EXE를 지정하고 verify_statement를 실행한다. contracts·expense·local_audit는 실사이트를 사용하므로 별도 승인이 필요하다. 일반 더블클릭 실행·창 종료·중복 실행도 배포 후보마다 직접 확인한다.

## 5. 보관·백업·이관

| 대상 | 위치·주의 |
|---|---|
| SQLite | 데이터 루트/saebom.sqlite3. 6개 테이블, JSON·파일 경로 포함 |
| 원본 PDF | document_root/세금계산서·계약서. DB disk_path가 실제 파일을 가리킴 |
| 거래명세서 | document_root/거래명세서. 저장 위치 변경의 PDF 이동 대상에 포함되지 않음 |
| 앱·사이트 프로필 | app-profile·browser-profile. 쿠키·사이트 기안이 있을 수 있어 외부 공유 금지 |
| 로그·실행정보 | app.log·instance.json. instance.json은 실행 때만 사용하며 토큰 포함 |

백업은 앱을 종료한 뒤 데이터 루트와 별도 document_root, 생성 거래명세서까지 함께 복사한다. 실행 중 검증에서는 sqlite3.Connection.backup을 사용한다. DB 파일만 단순 복사하면 현재 트랜잭션 상태를 놓칠 수 있으므로 종료 후 복사하거나 SQLite backup을 쓴다.

앱의 저장 위치 변경은 등록 PDF를 복사·해시 확인→DB 반영→이전 사본 정리한다(`saebom/store.py:330`). 실패 전까지 원본·설정을 보존한다. 임의 파일·거래명세서·사이트 프로필은 이동하지 않는다. 다른 PC 이관 시 documents.disk_path의 절대경로가 남는 문제는 해결하지 않았다. 일괄 SQL 치환을 자동으로 권장하지 않으며 복구 사본에서 별도 검증한다.

## 6. 장애 대응

| 증상 | 확인·대처 |
|---|---|
| 화면 연결 실패 | launcher 프로세스·app.log 확인. 새 실행에서 앱 화면을 열어 실행 쿠키 재발급 |
| 로그인 만료 | 현재 실행에서 다시 로그인. 재시작 전 잠금 쿠키는 재사용 불가 |
| 로그인 잠김 | 30초 잠금 경과 후 입력. 실패 카운터는 실행 메모리 전역이며 감쇠 없음 |
| 목록 전체가 비어 실패 | 전용 브라우저 로그인·계약 문서함 접근을 확인 |
| PDF 없음·이동 실패 | DB에 연결된 원본·디스크 공간·권한을 확인. 실패한 복사본으로 원본을 덮어쓰지 않음 |
| 상신 실패+site_draft | 사이트 기안 존재 여부를 먼저 확인한 뒤 재상신 판단. 로컬 상태 없음이 사이트 기안 없음의 증거가 아님 |
| 종료 뒤 작업 failed | 이전 running을 재시작 때 failed로 복원하는 정상 처리. 원본은 유지되므로 이력 확인 후 재실행 |
| Tk 선택창 문제 | 동기 라우트의 비메인 스레드 Tk 호출 한계. 경로 입력 방식 사용 가능 |
