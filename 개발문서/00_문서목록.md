## 2. 읽는 순서

처음 인수하는 개발자는 01→02→03→04→07→12 순서로 읽는다. 기능을 바꿀 때는 01의 추적표에서 해당 화면·API·모듈을 찾고 05·08·09와 해당 테스트를 함께 확인한다. 운영자는 12→11→14 순서로 읽는다. 문서의 `파일:줄`은 작성일 소스 기준이며, 변경 후에는 실제 심볼과 코드를 다시 확인한다.

## 4. 검증과 개정

문서 변경 시 `scripts/verify_docs.py`로 상대 링크·코드 줄 참조·라우트·테이블·Mermaid를 검사한다. Mermaid 검증에는 로컬 검증 전용 패키지가 필요하다(11번 명령). 자동 검사는 줄 번호의 존재를 확인하므로 의미 검토는 사람이 코드와 대조한다. 이번 작업에서는 메인이 코드 참조 30곳·전체 API·전체 테이블 열을 직접 대조했다. 다음 개정에서는 날짜와 검증 실행 범위를 13번에 남긴다.
