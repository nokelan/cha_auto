| 계층 | 입력·격리 | 검증 범위 |

## 3. 판정 불변 기준

`tmp/refactor-tools/judgement_snapshot.py`는 `compare.extract` 및 `compare.compare`를 직접 호출한다. `snapshot-before.json`을 기준으로 생성 JSON의 바이트를 비교한다. 입력별 값·원문 인용·페이지 번호, 페이지 텍스트 SHA-256, 모든 판정 check를 포함한다. 실행 시각·UUID 같은 변동값은 포함하지 않는다. 새 스냅샷으로 기준선을 덮어써 통과시키지 않는다.

총액 계약의 `period` 확인 필요는 실패가 아니다. 실제 이행·검수를 문서만으로 확정하지 않는 승인 정책이다. 규칙 변경은 이번 범위 밖이다.

실사이트용 `verify_contracts.py`·`verify_local_audit.py`·`verify_expense.py`는 이번에 실행하지 않았다. 마지막 스크립트는 실제 기안을 만든다. 실사이트 검사는 승인 후 격리 프로필·테스트 DB로만 한다. `SAEBOM_VERIFY_EXE`는 statement 및 contracts의 서버 시작 도우미와 이를 사용하는 실사이트 스크립트에 적용된다.

## 5. 재현 명령

프로젝트 루트 PowerShell에서 실행한다. 테스트 비밀번호는 기본 설정을 전제로 한다. `verify_refactor.py`는 자식 프로세스에서 비밀번호·EXE 검증 경로 덮어쓰기를 제거한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
.\.venv\Scripts\python.exe -X utf8 scripts/verify_refactor.py
npm.cmd install --prefix tmp/document-tools --no-save mermaid@11.12.0
.\.venv\Scripts\python.exe -X utf8 scripts/verify_docs.py
```

통합 결과는 tmp/refactor-review/report.json, 단계 로그는 같은 폴더, 문서 결과는 tmp/docs-review/report.json에 쓴다. 그림 검사 패키지는 앱 런타임·프런트 lock 파일에 추가하지 않는다.

## 6. 제한과 합격 기준

리팩토링만 했던 시점은 CSS 계산 스타일 동일·동적 텍스트를 제외한 화면 동일이 기준이었다. 이후 사용자가 앱 전체 2단 구성을 요청했으므로 최종 UI의 과거72장 픽셀 차이는 의도된 변경이다. `verify_refactor.py`는 현재 기능·화면검사 종료0, 판정 스냅샷 동일, 72장 캡처 완료를 합격 조건으로 삼는다. 과거 CSS 불변 검사는 `--compare-legacy-css` 옵션을 줄 때만 강제한다. 초기 결과는 tmp/refactor-review-before-layout에 별도 보존한다.

새 2단 화면은 html/body 전체 높이가 고정되고 본문·관련 링크가 각각 내부 스크롤한다. 기존 UI·원추출 검증의 footer 검사는 `scripts/ui_helpers.py`를 통해 본문 안에서 실제 휠로 확인한다. 우측 패널 위에 휠을 보내 본문이 움직이지 않는 것을 본문 오류로 오인하지 않는다. 문서 누락·Mermaid 오류0 기준은 유지한다. 자동 숫자만으로 시각 검토를 대체하지 않는다.

후속 배포 검증: scripts/verify_release.py는 실제 SAEBOM_VERIFY_EXE 배포본으로 기존4종 및2단 화면검사를 실행하고 정적자산·템플릿·ZIP을 대조한다. verify_ui·verify_raw_amounts·verify_auth_recovery도 EXE 선택을 지원하도록 보완했다. 2026-10-26 전체 배포검사5종 통과 및 기존 사용자 데이터로 정상 앱 실행을 확인했다.

미검증: 실사이트 최신 DOM·상신, 사용자 데이터로의 실제 상신, 새 PC 설치, Tk 네이티브 선택창의 실제 조작. 사용자는 새 앱 정상 실행을 확인했으며 에이전트가 일반 더블클릭 동작 자체를 재현한 것은 아니다. 프런트 단위 테스트·ESLint·부하 테스트는 현 프로젝트에 없다.
