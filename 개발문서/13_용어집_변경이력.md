## 1. 용어집

| 용어 | 의미 |
|---|---|
| 세금계산서 | 메일 첨부 또는 로컬 폴더에서 받은 대조 대상. PDF 텍스트를 규칙으로 판독 |
| 계약서 | 문서함 계약 목록의 첨부 PDF. 수입·지출 구분은 목록 정보도 함께 사용 |
| 원 추출값 | PDF에서 읽은 값. 수동 보정값과 별도로 보존·표시 |
| 근거 | 추출·판정에 연결된 원문 인용과 페이지 번호. 읽지 못한 값을 추정하지 않음 |
| 일치·불일치·확인 필요 | 규칙 기반 대조 결과. 일치는 실제 검수·법적 적합성 보증을 의미하지 않음 |
| period | 기간/이행 관련 check. 총액 계약의 이행 여부는 문서만으로 확정하지 않아 확인 필요 유지 |
| group | 총액·분할 계약에서 선택 세금계산서의 누적 금액 대조 |
| 수동 보정 | 원문을 바꾸지 않고 추출 필드의 적용값을 고쳐 새 결과·parent 연결 생성 |
| job | id·kind·status·message·done·total·errors·created 등을 가진 백그라운드 작업 |
| exclusive | 저장 위치 이동처럼 작업 제출과 겹치면 안 되는 배타 구간. 새 작업은 대기열에 쌓지 않고 거절 |
| ServiceHost | 믹스인이 요구하는 속성·메서드를 표현하는 정적 Protocol 계약 |
| catalog | 동기화된 메일·계약 목록과 저장 문서·비교 후보를 합친 화면용 자료 |
| contract_imports | 사용자가 가져온 계약 목록. 사이트 snapshot 갱신과 분리 보존 |
| results.summary | 이력 목록용 요약 JSON. 기존 NULL행은 첫 조회 때 data로 보충 |
| 거래명세서 | 수입 계약에서 월 범위를 확인해 만드는 xlsx. 템플릿 원본을 덮어쓰지 않음 |
| 지출결의서 | 지출 계약의 확인값으로 사이트에 상신하고 작성본을 검토하는 업무 |
| 품의완료 | 작성본 검토 전체 일치 후 저장하는 로컬 계약 상태 |
| site_draft | 사이트에 기안이 있을 수 있다는 표시. 클릭 후 예외·검토 불일치 때 true |
| SubmitUncertain | 제출 클릭 이후 결과가 확실하지 않은 오류. 재시도 전 사이트 확인 필요 |
| document_root | 원본 PDF·생성 거래명세서의 기본 보관 위치 |
| 데이터 루트 | SQLite·프로필·로그·instance.json 보관 위치. document_root와 다를 수 있음 |
| fixture | 테스트용으로 고정한 실제 형식 PDF. 사용자 운영 데이터와 구별 |
| 스냅샷 | 판정 불변 검사 JSON 또는 사이트 목록 갱신을 가리킴. 문맥으로 구별 |

## 3. 개정 규칙

소스·API·DB 구조 변경은 해당 문서와 테스트를 함께 고친다. 문서 날짜·코드 근거·검증 범위를 남긴다. 과거 검증 수치를 현재 결과처럼 바꾸지 않는다. 추정이 필요한 항목은 '(추정)'으로 표시하고 실제 실행 여부를 분리한다. 기존 초안은 _초안_리팩토링전에 보관하고 새 문서를 정본으로 사용한다.

계획·결정·교훈은 D:/LLMwiki에 기록한다. 프로젝트 안에 위키 사본을 만들지 않는다. 사용자 비밀번호·토큰·개인 이메일·브라우저 인증 자료는 문서와 위키에 기록하지 않는다.
